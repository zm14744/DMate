## 查到的方法及适用范围

### 1. 先明确输出协议，再讨论模型能力

私有候选首句要求“完整 JSON graphs 数组”，但 `VisionProvider` 只接受顶层对象，随后调用方再读取 `response.get('graphs')`。
两者存在歧义；明确的接口应写为顶层对象 `{"graphs":[...]}`，而不是让模型自行判断根类型。
不过旧试验没有保存原始 content，无法证明三次实际返回的是数组，也不能断言这就是失败的唯一原因。

本次只补充可区分的离线诊断：`output_error` 标记内容非字符串、JSON 语法、非有限数值或根类型错误；语法错误只记录行、列、字符位置。
已有 `invalid_output` 状态、整个根对象的严格校验、默认零重试、模型/Token/耗时记录和原文审计开关保持原语义。
不提取内层 JSON、不接受截断结果、不通过第二次请求修复格式，普通指标也不新增原始文本。
新增 9 项离线协议用例验证根类型、截断/多对象、非有限数值、原有格式兼容、usage 保留及无额外请求；全套 223 项 Python 机制测试通过。这些不是实际 `/ocr` 图像验收。

Qwen 官方 [Qwen-Agent 函数调用示例](https://github.com/QwenLM/Qwen-Agent/blob/main/examples/function_calling.py) 本身也提示 JSON 参数可能无效，需要错误处理。
工具调用或 `json_object` 参数不能直接证明任意现有远端接口会严格符合应用结构；不能靠安装客户端库就获得服务端受约束解码。

### 2. 明确坐标单位，保留原图局部细节

Qwen3-VL 官方 [2D grounding 示例](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/2d_grounding.ipynb) 明确默认定位坐标为相对 0–1000。
当前 DMate 要求 0–1 小数。官方默认不等于模型不能遵从 0–1，但值得研究显式坐标单位和单一转换入口，禁止按数值大小猜测单位或多次缩放。
若试验 0–1000，应仅在模型边界转换为既有内部 0–1，并验证裁剪坐标映射；不能直接替换内部几何协议。

官方 [Think with Images 示例](https://github.com/QwenLM/Qwen3-VL/blob/main/cookbooks/think_with_images.ipynb) 提供 `image_zoom_in_tool`，采用 0–1000 的局部范围。
这支持研究一次有针对性的原图裁剪，而非启动反复调用的智能体。
当前 `_data_url` 会缩至最长边 1600，教材宽 2048 的照片确实会被缩小；小权值、贴近交叉点的标签值得用原始分辨率局部读取。
候选已经有“最不确定子图”的裁剪，但还没有证据说明它能纠正这些错误；下一步更合理的是依据墨迹与标签歧义选择局部，保持最多一次复核，而不是再次复核整张图片。

优先验证对象必须来自现有失败证据：14.21 假 v10 与 v1 重合、14.22 权值错配、181129 和康奈尔外弧漏边。
坐标不可靠时继续画强确定性的红色编号图可能传播 NODE 错误，不能把这类辅助图当独立证据。

### 3. 学习候选边关联思想，暂不引入训练网络

[VisAdj 官方代码](https://github.com/Jiahao-Xie-86/VisAdj) 的 README 介绍 SAM 系列编码器、ASNS 稀疏候选边、LineGT 对共享端点的边进行关联建模，最后预测邻接矩阵。
它需要权重和专门数据流程，公开示例覆盖合成图、道路与视网膜图；这些信息不足以证明能直接处理 DMate 的带标签、带权、含重边教材照片。

可借鉴的是“每条候选边保留身份与证据，并在共享端点处检查矛盾”。现有实现已经保留边实例、路径和来源，但真图仍有 REVIEW 删除真实外弧、错误权值沿流程传播的问题。
普通二值邻接矩阵本身不能表达重边的不同实例与权值；任何借鉴都必须保留原有多重图表示。
NetworkX 可以检查身份、端点和重数一致性，不能判断一条照片笔画是否真实存在，也不能用图同构或度数模板反向补边。

## 后续优化顺序与停止条件

1. 先做协议与单位的离线验证，避免再次为无法诊断的格式错误付费。
2. 若继续改算法，集中于原图定位、标签/权值局部归属和外弧实例，保留证据；不继续堆模型或训练网络。
3. 当前不切换到未经跑通的简化候选，不新增付费测试，不重跑 44 图，不改生产配置或部署。

这些是有来源的改进方向，不是新的识别成功结论。上一轮真实错误与 0/3 整图结果保持有效。
