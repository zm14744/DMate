# 四图并发、用户编辑与确认后解题

更新：2026-10-27。默认版本为 `2026-10-27-fast-editable-v4`，引擎配置名仍为 `agent-tools`。本文说明当前默认流程；此前 `DMATE_RECOGNITION_ARCHITECTURE.md` 等 semantic 系列文档保留历史设计，不再规定默认模型调用顺序。目标是快速得到可核对、可修改、可用于解题的结构，不再要求 86 张图片首次自动识别全部正确。

## 识别与资源调度

一次可选择、拖入或粘贴最多 4 张原图。每张图分别建立请求、原图摘要、状态和计时；结果可乱序完成，已完成的图立即可编辑。取消或失败只影响对应任务。服务端同时接纳最多 4 个识别任务，超额请求明确返回忙碌状态。

每张图片的默认流程：

1. OpenCV 快速预处理、版面和节点候选；复杂版面才选择 PP-DocLayoutV3。
2. 提交 PaddleOCR Small 本地任务，同时开始一次 Qwen3-VL-Plus 完整图文识别。主读使用原图、最多四个已生成的图块放大窗口和当时已就绪的候选，不等待 Small 排队完成；放大窗口明确归属同一原图，正文碎片不作为图块发送。
3. 汇集本地候选，执行程序、JSON Schema 和 NetworkX 检查。题干由同次 Qwen 主读保留全部小问、公式和必要图例，本地规则、知识点索引及有限数学语法检查提供辅助参考。
4. 有具体疑点时，最多调用一次 GLM-5V Turbo 局部复核。连接或方向疑点按需启用自有边追踪，复杂路径再启用 sknw；不会对所有图片常规执行全部重工具。
5. 再次执行结构检查，生成统一语义结构和可编辑展示。题干明确依赖的颜色、线型缺失会保留具体疑点；普通装饰、精确坐标不作为完成门槛。

LangGraph 组织阶段，DMate 内部工具注册器记录校验与辅助工具调用。识别阶段不默认调用 DeepSeek。题干参考不可据题名或常见图性质补删原图节点、边。

四个远程视觉任务可以并行。本地重工具使用共享优先队列和跨进程锁，Small 优先于待执行的 Layout、路径任务，限制内存争抢。排队、运行和取消状态分别记录；请求退出时取消尚未开始的工作，并回收已运行的有界任务。GLM 缺少凭据或失败时保留可编辑结果及未解决项，不以追加 Qwen 调用掩盖失败。

## 编辑、确认与解题

编辑器同时展示原图和结构图，支持节点增删与标签、边端点、方向、权重、独立重边数量、自环、题干和图例修改，也支持子图新增、合并和节点归属调整。移动节点不得留下跨子图的悬空边；撤销、恢复初稿和删除确认用于纠正误操作。显示布局不要求像素级复刻原图。

用户核对后点击确认，服务端重新校验并生成绑定当前浏览器、原图、任务和结构版本的确认记录。确认本身不会解题；用户另行点击“解题”才调用 DeepSeek。再次编辑立即使前端旧确认失效，新确认也会使服务端旧令牌失效。解题请求携带的结构必须与确认摘要一致，不能用旧识别结果或其他图片的结构替换。

DeepSeek 接收用户最终确认的题干和图结构。适用的度数、连通性、最短路、最小生成树等计算由 NetworkX 提供；明确的单图邻接矩阵幂、秩、行列式请求可使用受限 SymPy 工具。该能力不等于任意自然语言推导都已自动得到数学证明。

## 时间、状态与部署

单图完整识别的性能目标为 **120 秒**，包含所需工具、模型、最终校验和展示。前端各自从任务创建计时，更新结果卡片并经过浏览器绘制帧后结束计时；超过 120 秒仍显示真实处理状态，允许用户取消，不强制截断为成功。

当前独立故障预算为 200 秒，单次远程调用最多 75 秒，最多 2 次远程调用，无额外网络或 JSON 恢复调用。故障预算是运行保护，不是性能达标线。`partial` 或失败结果即使很快返回，也不计作完整识别性能通过。`complete` 和结构校验通过只说明本次流程完成、数据合法，不能证明每条边都符合原图，仍须用户核对。

容器默认命令已为四图请求保留足够 HTTP 线程：

```bash
gunicorn -w 1 --threads 8 --timeout 300 -b 0.0.0.0:${PORT:-8080} app:app
```

部署平台若覆盖启动命令，也需同步更新为 8 线程；旧的 2 线程配置不能承载四图同时识别及取消、健康检查等请求。本地推理并发由工具调度器限制，不通过压低 HTTP 线程来限制内存。

必要配置为 `DASHSCOPE_API_KEY`；局部复核使用 `ZHIPU_API_KEY`，解题使用 `DEEPSEEK_API_KEY`。默认启用新版流程；排查时检查是否有旧的 `DMATE_GRAPH_NEXTGEN=0` 或 `DMATE_GRAPH_PIPELINE=evidence-two-pass` 覆盖。确认记录默认存于临时目录的 SQLite，可通过 `DMATE_GRAPH_CONFIRMATION_DB` 指定路径；清空或更换该数据库后旧确认需要重新提交。

部署后查看 `/health` 的 `graph_nextgen_version`、`runtime_source` 和 `recognition_budget`，确认运行的源码与版本。默认预算应报告 200 秒、120 秒目标、2 次调用、4 张并发。GitHub 提交成功与线上服务完成重部署是两项独立事实。

## 验证方法与已知边界

安装项目依赖和 pytest 后，在仓库根目录执行核心回归：

```bash
python -m pytest -q \
  tests/test_graph_fast_pipeline.py tests/test_graph_local_scheduler.py \
  tests/test_graph_upload_tasks.py tests/test_four_image_upload_route.py \
  tests/test_graph_confirmation.py tests/test_visual_graph_editor.py \
  tests/test_fast_runtime_reporting.py
```

编辑器测试需要 Node；实际浏览器验收还需要 Playwright、Chromium 和已核验的前端 CDN 缓存。配置本机路径并使用全新的结果目录后运行：

```bash
export DMATE_BROWSER_EXECUTABLE=/usr/bin/chromium
export DMATE_BROWSER_CDN_CACHE=/path/to/verified-cdn-cache
export DMATE_EDITABLE_BATCH_OUTPUT=/path/to/new-private-result-directory
python -m pytest -q tests/test_editable_batch_browser.py
```

四图浏览器验收使用实际 Flask 路由、LangGraph、编辑器、确认接口与解题输入，仅替换外部模型和 Paddle 边界。它验证四路重叠、乱序完成、失败/取消隔离、编辑后结构同步和旧确认拒绝；不能据此宣称真实模型精度或生产性能通过。真实图片测试使用 `scripts/benchmark_graph_first_pass.py --jobs 4`，保存首次响应和原图摘要，按节点、端点、方向、权重、题干分别检查。

已完成的 **fast-v1** 实测覆盖 12 张分层样本、21 个数学子图：分图清单 21/21，10 张节点数量正确；12 张服务端耗时约 11–69 秒，11 张流程完整、1 张为 partial。箭头方向、少数图的端点和权重绑定仍有明显错误。包含真实浏览器展示的 4 张中，3 张完整结果在 120 秒内，1 张 partial 不计通过。这不是 86 张全量测试或总体准确率统计，也不是当前 v3 的性能证明。

v2 增加同一次 Qwen 主读内的有限思考和逐箭头核对提示，并在已有的一次局部复核中传入题干必要属性与圆点候选。对 4 张有已知错误的原图分别执行一次真实并发请求，约 23–45 秒返回，4 张流程完整，但仍有箭头、端点或点/边名混淆错误。多图样本中一幅子图被修正，整体连接准确性没有可靠改善；缺失颜色检查能触发复核，不能保证模型给出的颜色与正确边对应。该测试未包含浏览器渲染，不能单独作为完整 120 秒验收证明。

核心编辑与确认链路已通过 22 项浏览器回归，四图场景内部 24 项检查全部通过；本地真实 Small 四任务依次约 12/22/34/44 秒完成，没有忙碌跳过。全套回归 2685 项通过，1 项历史回放因测试期间文档改动触发工作树快照检查；冻结文件后，该回放文件 37 项全部通过。上述证据分别衡量交互正确性、资源调度及模型输出，不能互相替代。
