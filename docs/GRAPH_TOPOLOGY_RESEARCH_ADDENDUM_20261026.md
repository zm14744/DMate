# 图连接器与拓扑恢复：定向研究补充（2026-10-26）

## 状态和范围

这份补充记录诊断后的研究与架构提案；撰写和查证期间生产识别源码保持冻结。提案本身不代表下文方法已经实现或真实识别验收通过，后续实际实现见[架构说明](GRAPH_EVIDENCE_ARCHITECTURE_20261026.md)。本轮只核查能够解释具体失败机制的一手资料；不导入额外视觉模型，不将用户原图、私有标注或针对某一张图的规则写入公共代码。

固定分工仍是 Qwen3-VL-Plus 提供视觉语义，PaddleOCR Small 和 PP-DocLayoutV3 提供文字、版面证据，DeepSeek 只校正文字。每张原图最多两次 Qwen 请求，无自动重试。目标运行环境是 2 核 CPU、4 GB；论文运行数据不等于该目标环境实测。

## 一、为什么需要调整中间表示

当前诊断指向四个不同对象被过早合并：数学顶点、像素交叉口、可见笔画和完整连接器。圆形节点内部的数字可以产生小圆响应；一条空心箭头有两侧轮廓；一条虚线包含多段不连通墨迹；两条平行弧可以共享相同端点。把它们都简化为“骨架从中心 A 到中心 B 的一条路径”，会同时造成漏边、错端点和重边误计。

像素覆盖支持说明候选附近存在墨迹，不能单独证明这些墨迹属于同一条数学边。相反，连接器中心线处没有墨迹，也可能是空心箭头的正常结构。后续应显式保存节点轮廓、出线端口、笔画片段、间隙、箭头头尾与连接器实例，然后再形成数学图。

## 二、五项一手研究及采用边界

### 1. Optical Graph Edge Recognition，Opmanis，IVAPP 2018

来源：[出版商页面](https://www.scitepress.org/Papers/2018/65504/)；[出版商正文](https://www.scitepress.org/publishedPapers/2018/65504/pdf/index.html)。核查范围：正文第 2、3 节及实验设置；直连正文出现访问错误时，读取了搜索服务返回的出版商正文摘录。

方法先以 Sparse Pixel Vectorization 生成方向、宽度一致的线段，虚线的每个 dash 独立保留；再建立线段端点邻接图，从已识别节点向外追踪。续接代价结合已有链的较长尺度方向、间隙方向和转角，避免单个短 dash 主导方向。节点输入应有宽高或像素集合。论文处理无向多重图和自环，但假定合理间距、节点不重叠、背景颜色可确定；2400 个合成图实验不是复杂纸面照片验收。

**本项目采用建议：**借鉴“片段图 + 有限间隙续接 + 历史切线”，替代对整条虚线采用严格最大/最小间隔比。节点轮廓和端口必须先可信。未核实可复用的官方实现或代码许可证，只作方法参考，使用现有 OpenCV/NumPy 独立实现局部机制；CPU 成本须另测。

### 2. Arrow R-CNN，Schäfer 等，IJDAR 2021

来源：[官方全文，特别是 4.2、5.3、5.5 节](https://link.springer.com/article/10.1007/s10032-020-00361-1)。

论文将箭头作为对象实例，同时预测头、尾关键点，再关联节点。它提醒我们高重叠的箭头框不一定是重复检测；但其后处理假设同向同端点最多一条边，并按此去重，不能用于 DMate 的多重图。实现采用 PyTorch、maskrcnn-benchmark、ResNet-101/FPN；文中的低于 100 ms 推理是 V100 上、图片已缩放入内存的结果。误差分析也包含头尾错配。

**本项目采用建议：**只借鉴实例、头尾和节点附着分离的表示，不增加该模型，不照搬端点对去重。论文没有证明能够正确把所有空心双轮廓箭头合成一个实例，相关轮廓配对仍是本项目待验证设计。未核实完整官方推理实现及其许可证；数据转换仓库不能当作模型实现授权。

### 3. Vectorization of Line Drawings via PolyVector Fields，Bessmeltsev / Solomon，TOG 2019

来源：[作者论文全文](https://arxiv.org/html/1801.01922v2)；[作者参考实现](https://github.com/bmpix/PolyVectorization)；[MIT 代码许可证](https://github.com/bmpix/PolyVectorization/blob/master/LICENSE)。

论文在墨迹窄带上估计可同时容纳两组方向的场，结合平滑与图像切线约束，再追踪、分组和恢复拓扑，避免单方向场在 T/X 交叉处混线。其两方向表示不覆盖任意多方向密集交点，阴影填充和极低分辨率也是限制。论文报告在 4 核 i7、32 GB 内存机器上通常约 20 秒到超过一分钟，不能视作轻量默认环节。

官方代码为 MIT，可在保留版权和许可的前提下评估复用；但依赖 C++、OpenCV 2.4、Boost、Eigen，可选 Qt。README 明确公开版本不是论文性能测试用的优化版本，且简单亮度阈值可能漏线。因此当前只借鉴交叉处同时保留多方向假设的思想，不将整库加入生产依赖，也不把其几何图直接当成数学图。

### 4. Vectorization of line drawing image based on junction analysis，Chen 等，2015

来源：[作者托管全文](https://cecilialeiqi.github.io/vectorization.pdf)，重点为第 4 节与 5.2 节。

方法结合中心线与轮廓追踪，以亮度极坐标映射估计分支数和方向，再用轮廓弯曲程度判断分支连续性。它提供了“数到几条分支”之后仍需判断分支配对的直接依据。作者报告的 0.2～3 秒使用了 GPU 预计算；邻近多个交点仍可能失败，部分复杂例子需要人工分裂、合并或移动交点。

**本项目采用建议：**局部极坐标方向、轮廓连续性可以用现有 CPU 工具在有界 ROI 内试验，不能照搬“环上有 4～6 个峰便否决”的简化规则。节点出线扇区、箭头头部和普通交叉应分别建模。未核实官方代码及许可证，不新增 GPU 依赖，也不引用其时间作为 CPU 承诺。

### 5. Vectorizing Line Drawings of Arbitrary Thickness via Boundary-based Topology Reconstruction，Zhang 等，CGF 2022

来源：[出版商页面和摘要](https://onlinelibrary.wiley.com/doi/10.1111/cgf.14485)。本轮可核查范围为官方摘要、元数据和参考文献；未完整复现或核实代码。

该方法先取得骨架，再根据边界连续性判断骨架点是否可靠，保留可靠部分、重建不可靠部分，重点针对粗线交叉。它支持将轮廓作为骨架之外的证据，但没有从摘要证明“空心双轮廓箭头就是一条语义边”，更不能直接推广到全部多重图。

**本项目采用建议：**把边界连续性作为粗线、双轮廓附近的可靠度特征，先做受限实验。官方实现、许可证及目标 CPU 成本未核实，因此仍是思想借鉴，不是可安装生产依赖。

## 三、建议的数据契约

| 层 | 应保存的信息 | 不能替代的判断 |
| --- | --- | --- |
| 数学节点实例 | 稳定 ID、中心、轮廓/椭圆/多边形、外接框、轮廓置信度、与文字的归属 | 一个中心附近有墨迹不代表节点边界已定位 |
| 节点端口 | 外轮廓上的附着位置、外向切线、局部笔画宽度/颜色、所属节点、置信度 | 相同节点可以有多个端口；不能用最近中心直接合并 |
| 笔画片段 | 原始坐标轨迹、左右边界、宽度、颜色、端点切线、来源图层 | 片段不自动等于一条完整边 |
| 连接器假设 | 片段列表、头/尾/方向证据、端口、显式间隙与遮挡、原像素引用、竞争假设 | 墨迹连通不自动等于数学连通；头尾不明时方向仍未知 |
| 数学边实例 | 独立 edge ID、端点 ID、方向、重数中的实例身份、标签/权值 | 相同端点和方向的两条独立轨迹必须允许同时存在 |

轮廓应可表达非圆形、轻微椭圆、缺损和低置信度。发现一个数字内部的小圈时，不能因其局部环响应较高就立即把它当成节点外边界；需要外轮廓、包围关系、附近节点尺度分布和出线附着一致性等共同证据。尺度分布只是软证据，不能强迫大小不同的合法节点变成同一半径。

## 四、面向具体机制的设计推导

以下是 DMate 的工程提案，不是上述论文已经验证的结论。

### 节点轮廓与端口

先在节点局部 ROI 中枚举轮廓假设，保留外轮廓及其置信度，再分析轮廓外的笔画附着。标签 OCR 框帮助区分内部文字；不能直接擦掉所有文字框，因为线条可能穿过文字或被权值遮挡。对不确定外轮廓保留多个有限假设，避免把一次错误半径同时传播给去节点、播种、目标匹配和像素支持。

节点边界之外应保留端口到真实可见笔画的短连接关系，圆心连接段仅用于展示和协议对齐。检查第三节点时使用其轮廓区域；绕着一个已知节点的圆圈走到另一条出线，不能变成跨过该节点的新边。

### 空心箭头、粗线和重边

对空心箭头建立一个含两侧轮廓、箭头头部和尾部的连接器假设。只有颜色、宽度变化、共同头尾及轮廓闭合/附着共同支持时才配对；两条近距离平行线不能仅因相邻就合并。中心线可以是派生几何，其支持应回查轮廓而非要求中心每一点有墨迹。

重复判断限定在节点外的连接器实例上，显式排除节点内部和为了协议补齐的圆心段。需要比较独立笔画走廊、两侧轮廓归属以及间隙证据，同时保留同向平行边、反向弧和自环的独立身份。端点对、包围框 IoU、整条路径的平均距离都不能单独决定去重。

### 交叉与出线扇区

交叉处保留有限的分支配对假设，利用进入/离开方向、两侧轮廓连续性和路径历史判断是否直行。交叉分析的完整窗口应避开已知节点轮廓、端口扇区和箭头头部；半径之外仍可能属于一个节点的密集出线区域。

局部检测到多分支只能说明存在歧义。既不能直接添加数学顶点，也不能因为候选有一次折向就永久删除真实边。对明显切换到别条笔画的路径应拒绝；对端口附近追踪失真的路径应重新生成局部假设，而不是放宽全部交叉规则。

### 虚线和文字遮挡

虚线以 dash 片段和间隙序列表示，间隔统计区分完整内部间隙与端点截断残段。使用宽度、颜色、切线、曲率、局部间隔分布和分支竞争共同限制续接，允许合理变化；不以单个短间隙把整条虚线否决，也不靠闭运算把任意白缝填成边。

文字遮挡属于另一种显式间隙原因。OCR 区域只能提供遮挡假设，仍需两侧走向与连接器身份相容。文字遮挡、虚线间隔、透印弱线应分别记录，不能混成一个“允许缺像素”的布尔开关。

### 颜色、浅线与低分辨率

沿用原始 RGB、归一化辅助层和强/弱墨迹分层。弱线进入待复核假设，不直接删除，也不能自动升级为真实边。疑难 ROI 回到原始分辨率分析，保留细小平行间隙和浅自环；从锐化图产生的结构不能成为新的原始证据。

全图工作分辨率是资源控制，不能被误解释成所有局部细节的充分采样。最终检查须明确一段结构是原图可辨、辅助层可见但原图不确定，还是已低于可可靠分辨的尺度。

## 五、2 核 4 GB 下的实现次序与成本边界

优先使用已在项目中的 OpenCV、NumPy、Pillow，不增加 GPU 推理器。按节点和疑难连接器的小 ROI 顺序工作；复用距离场，保留稀疏片段表与局部轮廓，不为每条候选复制全图。给轮廓候选数、片段邻居数、交叉竞争路径、ROI 总像素及运行时间设置显式资源上限，触顶时输出不完整诊断。

第一批实验应是节点外轮廓/端口、虚线片段续接和连接器实例去重；第二批才是在真正复杂交叉 ROI 内尝试多方向场或边界优化。PolyVector 的整图求解不进入默认链，其他研究的 GPU 指标也不作为时延预算依据。任何新的局部优化都应记录 CPU 时间、峰值内存、ROI 数量和触顶情况后再决定是否启用。

Qwen 的两次调用保持固定预算：第一轮建立全部子图、节点与形状语义；本地生成并组织连接器假设；第二轮复核全部子图、端口、竞争路径和遗漏。第二轮可以提出有证据的新节点/连接器，但不能用视觉票数替代原图可追溯性。DeepSeek 不改变图结构。

## 六、下一阶段验收应分开证明什么

1. 节点边界与端口测试覆盖不同尺寸、非圆形、内部数字、淡色、模糊和不等半径；验证轮廓置信度，而不只看圆心。
2. 连接器测试覆盖双轮廓箭头、同向平行弧、反向弧、自环、粗线偏移、交叉直行、出线扇区、可变虚线和文字遮挡；每种都有易混淆反例。
3. 候选层隔离实验只证明给定参考节点后的候选可用性，必须同时记录错误端点、重复实例和支持误判。端点重数容量是可能匹配上界，不是识别准确率。
4. 冻结版本后对每张原图进行一次真实全链识别；单独记录子图归属、节点、边端点、方向、重数、自环、标签/权值、文字公式、完整性和展示。没有真实模型输出时，不能宣称原图全对。
5. 受控 2 核/4 GB 整链性能测试与本机 CV 探针分开报告。Paddle 并行负载下的局部耗时不能冒充部署指标。

## 结论

本轮最有价值的变化是把“节点中心之间的一条像素路径”升级为可追溯的“节点轮廓—端口—片段—连接器实例”表示。研究支持这些机制值得验证，同时明确了不能照搬的假设与成本。后续修复必须先落实这一契约，再用通用参数族和冻结原图验证，而不是不断增加针对个别样本的阈值补丁。
