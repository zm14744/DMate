# DMate 图结构像素算法调研与优化（2026-10-21）

## 目标及限制

本次只调整 CPU 图结构重建，不改变 DeepSeek 数学解题及刚接入的
`qwen3-vl-235b-a22b-thinking` 远程图片识别模型。服务器继续按 2C/4GB 设计。
任何视觉模型的口头描述都不能替代完整顶点—边集合的逐边验证。

## 借鉴资料（技术思路，不复制第三方实现）

1. GitHub `image2graph`：
   https://gist.github.com/GianlucaCarlini/7b6486444867af6d25c02c9e4a58fd5c
   采用二值骨架、连通域、拓扑追踪；在离散数学交叉线处必须注意：
   无标记的像素交叉 **不是** 图论顶点，也不能沿交叉随意转弯。
2. Knossos & Ariadne：
   https://arxiv.org/abs/2610.04721
   https://github.com/bangwayne/knossos_Ariadne_Public
   先提取节点、再预测每个节点连接关系；属于可借鉴的架构思路，
   不是 OpenCV 的即插即用算法，尚未在 DMate 上训练或验证。
3. Hugging Face TopoBench：
   https://huggingface.co/datasets/WayneGuo0011/TopoBench-180
   公开 162 份拓扑标注，只有部分可直接再分发图片；需遵循许可，
   测试时按有原图和只有源链接两类区分。
4. CSDN 骨架细化实例：
   https://blog.csdn.net/weixin_29041195/article/details/167816141
   提及 OpenCV contrib 的 `ximgproc.thinning`、线条中心线和节点追踪。
   通用道路网络的每个交叉点可能是真路口，**不能**直接套到数学图中。

## 本次已落地：跨像素检测器的顶点对应和边集冲突处理

原 `graph_recognition.recognize_graphs` 在实心点检测器返回**一个**
非空图时立即结束，未启动后续原像素盘—盘连线检测。
现在当实心点检测器只识别到单幅图时：

- 继续运行不同几何依据的原像素连线检测器；
- **根据顶点的归一化坐标建立一对一映射**，不拿 `v1/v2` 编号硬比；
- 同一图的可靠共同边仍被确认；任一方多出的边列入
  `uncertain_edges`，并将可信度降为 `partial`；
- 顶点数有分歧但空间区域明显重叠时，将可信度降为 `partial`；
- 两个检测器图形无法可靠配对时不造边；多图路径仍走原来的
  已有像素检测逻辑，避免回归原来的四图/六图识别；
- 英文图论题经过入口关键词判定后，不再被 v2 的中文专用预过滤掉。

这是一项**降低伪确定性、增加候选结构交叉核验**的改进，不表示
曲线、箭头、自环或重边已经可以被 OpenCV 完整识别。
两套检测器来自同一张像素图，互相同意也不证明绝对正确。

## 公共 Graphviz 真实样本 CI 复核（新模型未加入本测试）

2026-10-21 本次提交 `59e06f4` 自动化公开 Graphviz 样例跑完：
15 个来源中 14 个可渲染、1 个原始 DOT 语法错误；成功渲染的
14 个正常图片 **0 个满足完整顶点数与边数同时正确**，并且
42 个变体中曾有模糊/缩小图片把错误子图错误标记为高可信度。
这份样例涵盖复杂工业/流程图，不等同于离散数学课件图，
但足以证明**不能只以 CI 成功或检测器返回 `high` 视为识别正确**。

本轮后续修复：当一个独立像素检测器不能得到另一检测器的单图印证时，
即使它内部声称 `high`，也降级为 `partial`，避免以错误高可信度
覆盖云端 Vision 的逐边判断。基准脚本还新增了跨 3 种图像变体的
错误高可信度统计，不再只计算正常分辨率图片。

公开测试 CI：
https://github.com/zm14744/DMate/actions/runs/39607040898

注意：`unsafe_high_all_variants` 统计的是*顶点/边数不符且像素检测器
报高可信度*，不是 Qwen 的结果；它不替代逐边精确率。
