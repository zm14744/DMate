# 千问图结构草稿与按需复核（2026-10-29）

这是图结构复核版本 v1 的回归记录。后续图片识别与绘图分离的当前界面及同次文字输出，见 [图片识别与独立绘图](SCAN_AND_DRAWING_WORKSPACES.md)。

上传入口 `workflow=auto_graph` 现在返回可编辑点边草稿，而非只有分图范围。主模型为 `qwen3.8-flash`，开启思考，思考预算 4096；文字仍由独立标签页框选识别。识别阶段不调用 DeepSeek，也不默认运行 OCR、Layout、sknw 或另一家视觉模型。手动绘图入口和用户确认后解题的结构绑定保持原有流程。

实现位于 `graph_qwen_targeted.py`、`graph_qwen_targeted_review.py` 和 `vision_provider.py`。LangGraph 组织主读取、局部候选、按需复核及最终检查；DMate 工具注册器记录原图来源、输入输出契约、耗时和实际执行情况。

## 针对的问题

- **漏边和端点位置偏差**：统一编辑器和节点定位工具的 0–1 坐标，原像素定位只调整已有节点的位置，不改变节点身份或数量。修复旧 CV 候选中元组、NumPy 标量无法通过 JSON 契约的问题。高分缺失笔画触发复核；节点未能可靠定位时，较弱笔画也可以作为问题候选。
- **细小箭头及整图类型误判**：一个较强箭头候选，或两个不同位置的较弱候选，可以触发逐源节点读取。只传待检查的端点，不将工具预测方向或第一次的图类型传给复核者。原图、完整放大图与端点连线裁图来自同一张图片，不画预测箭头。
- **细桥连接被误拆为两幅图**：小规模双图草稿额外检查跨框笔画。候选不直接合图；两个真实端点的读取一致并确认有连接后，才归入同一图，保留原有节点和边。
- **权值对应和保守合入**：同一笔画两端必须对端点、方向、权值、边名一致，才修改该笔画。双方均否认的工具假阳性被丢弃；不一致、未知、复核失败、复杂重边和自环保留疑点，不以模板、度数或题意补边。复核后仍读成无向、却无法解释箭头候选时，方向保留 unknown。

逐源分组借用了 Ariadne 的问题分解思路；每组三个源节点，多个组放入同一次复核请求。这不是论文训练或多次独立推理的完整复现，同一模型同次输出的两端一致也不证明图像识别一定正确。

## 最后一轮真实 API 回归

沿用裸模型测试前冻结的 10 张原图，不将参考答案、期望边表或图片 ID 输入识别代码。四个图片任务并发，每图独立计时；本地 CV 通过共享资源锁执行。本轮实际使用 13 次视觉请求（7 张一次、3 张两次），无自动重试或跨模型回退。

| 指标 | 本轮结果 |
| --- | --- |
| 返回可用草稿 | 10/10 张 |
| 分图数量 | 10/10 张正确，共 11 幅数学图 |
| 顶点数、边数 | 各 11/11 幅正确 |
| 边连接端点 | 102/102 |
| 箭头方向 | 57/59，96.6% |
| 权值及所属边 | 54/54 |
| 每张核心结构全部正确 | 8/10 张 |
| 服务器完整处理 | 14.1–82.0 秒，中位数 26.3 秒 |
| 本地 Chromium 编辑器渲染 | 10 张全部保留点边、方向和权值，最长 138.8 毫秒 |

此前同批裸千问思考输出为：端点 101/102、方向 46/59、权值 54/54、整张核心结构 8/10。本轮修复了漏边，细箭头的方向读取明显改善，但两张图各剩一条 C/D 之间的反向错误；整张零错误比例没有提高。两轮提示词、思考预算和服务时段不同，不能据此证明单个算法的因果收益或生产速度。

本轮服务器计时包含主读取、候选工具、实际必要复核和最终校验。浏览器渲染另行对这 10 份真实结果测试，未包含用户网络上传和下载时间；没有将两者冒充为线上端到端测量。120 秒是性能目标，200 秒是操作故障窗口，单次模型请求最多 80 秒。预算或网络故障不能变成“已完成”；必要复核失败返回待核对草稿，最终 JSON Schema 和 NetworkX 检查仍执行。

这些数字只覆盖上述样本，不代表全部 86 张测试图或生产总体准确率。本轮未评估文字、小问或标签大小写的独立准确率。JSON Schema、NetworkX 只校验结构合法性和记录保存，不认证原图准确性。
