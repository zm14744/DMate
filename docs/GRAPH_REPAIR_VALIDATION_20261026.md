- 题干：定位证据逐项归属和冲突解释；无图文字校正仅允许明确等义字形/空白；实质改字必须由原图复核，组合编辑另作全文检查。
- 状态：图完整、题干完整和模型执行成功分开；新路由异常失败关闭，不能启动旧链额外调用；文字超限不再误报公式降级。
- 前端与评测：透明图预览白底；逐实例展示边；严格核对两次Qwen实际发送记录；真实浏览器重放绑定首次响应，阻断重新识别和外网请求。

## 独立审查的额外发现

1. 有限字符/关键词保护遗漏中文颜色、指令、逻辑与组合编辑。最终完整内容签名封闭旧9个反例，36项编辑按新职责边界符合预期，48项视觉/本地题干冲突须有解释，11项空间归属正反例通过。

独立复验进一步覆盖了中段之外的头/尾端口绕路。正确白中轴即使没有黑墨也可接受；远处空白绕路、头尾端口容差条带中的96像素绕路、互换同端点的两条独立箭头路径均进入pending。真实两条平行空心箭头仍分别接受且不去重。六项独立反例与正例已通过，所有中止批次保留。

## 原图管线与首次响应弹窗复验入口

在隔离测试环境提供模型凭据，保留本报告对应代码和原始53张文件，然后运行：

```bash
python scripts/benchmark_graph_first_pass.py \
  --manifest /private/manifest.json \
  --annotations /private/annotations_slides.json /private/annotations_supplement_photos.json \
  --local --output /private/new-frozen-first-pass-run

python scripts/verify_graph_first_pass_ui.py \
  --run /private/new-frozen-first-pass-run \
  --manifest /private/manifest.json \
  --browser /private/chromium/chrome \
  --cdn-cache /private/verified-public-js-cache
```

前置检查可使用`--check-only`，它不会调用模型，也不能产生完整识别证书。每次运行必须使用新的仓库外目录。首次运行脚本保留全源码快照、原始字节摘要、一次attempt、实际PreparedRequest发送、模型记录、原始响应及独立评测；后续UI重放仅追加展示证据。HTTP模式若缺少服务端源码和传输记录证明，不能认证为完整成功。

当前脚本的范围是`local_pipeline/http_ocr_response`加`response_dialog_replay`，不是完整应用上传验收。它们分别输出`pipeline_status`、`frontend_status`、`pipeline_ui_status`及通过数量；本地应用状态为`not_run`，HTTP实际已响应时保留HTTP事实但应用为`not_certified`。`certified_passes`和`application_certified_passes`保持0，顶层没有无范围限定的pass，未知或缺失执行模式失败。运行/重放的退出码2表示完整应用未认证，即使组件可以全部通过；预检的ready/blocked另记。现有前端上传确实提交原始File且无预压缩，但这是源码检查，不能代替真实上传观察。

完整应用验收仍需同时满足：从实际文件选择/上传进入正确`/ocr`路由、配置与就绪状态；原图与源码一致；两个Qwen成功发送且均正常结束；全部数学子图、节点、边端点、方向、独立重边、自环、权值、边名、样式、题干正确；所有不确定项解除；同一首次响应在桌面与手机实际展示相符；目标容器资源门禁通过。当前管线/弹窗工具没有实现全部应用证据的自动认证。任何一项缺证据都不报告整图单遍通过。
