# DMate 说明文档与 175 项自测表审校记录

**范围**：2026-10-13 源码快照 `296b3388`；本次只修订 Markdown 文档和 Excel 测试文字，不修改应用业务源代码，不代表线上版本已经重新部署。

## 关键修正

1. **模型思考强度**：简单题 `none`；中等与困难均 `high`。不再宣传困难题 `max`，移除不存在的 `HARD_MAX_OUTPUT_TOKENS` 文档配置。
2. **出题难度**：独立出题、同知识点参照出题、错题复测都以中等为默认目标，不继承参照题难度；模型实际生成仍有偏离可能。
3. **云同步双重大小限制冲突（代码问题，尚未修复）**：`app.py` 的 `MAX_SYNC_JSON_BYTES = 12 * 1024 * 1024`，但 `app.config["MAX_CONTENT_LENGTH"] = 8.5 MiB` 对所有 HTTP 请求先行生效；当前无法保证接收 12 MiB 的同步数据，达到全局上限即会拒绝。建议让 `/sync` 与 OCR 使用分别合理的请求限额，补充边界测试。
4. **并发同步**：目前前端检测 409 后自动合并并重试，分叉会话可能保留双分支；`force=true` 会被后端以 HTTP 400 拒绝。已更正 API 请求说明和表格 S-004。
5. **多考点复测**：结构化 `retest_core_points` 非空时后端逐项检查是否命中，前端最多收集四个核心考点；不应写成只要命中一个就能通过。
6. **复合出题**：加入“出题并给答案”的专项自测项，明确区分普通出题隐藏答案与用户明确要求时显示答案。
7. **游客与登录的刷新行为**：游客的会话和外观不作持久恢复承诺；登录用户恢复属于独立测试场景。
8. **证据与预设**：K 列保留 175 个预设“通过”，J 列明确“本轮未逐项实测”；静态检查项目可据实际命令填写。不能将预设通过当作实际通过率。
