# DMate 离线模式设计

## 1. 产品决定

采用**一个 DMate、两种工作状态**，不再维护一个功能重复的独立离线聊天产品。

- 在线状态：保留现有完整 DMate。
- 离线状态：进入本地学习工作区，只提供无需云端服务的六个模块。
- 在线与离线共用知识点编号、内容包格式和个人学习数据模型。
- 离线模式不要求安装本地大语言模型，也不把 OCR、语音或云端 AI 伪装成离线功能。

### 离线工作区范围

1. 错题本：查看、编辑、分类、复习。
2. 概念笔记：查看、新建、编辑、删除。
3. 独立绘图：创建、编辑、保存、导出。
4. 知识图谱：浏览、搜索、查看前置知识和关联知识。
5. 题库：按章节、知识点和难度筛选，练习、判题、查看答案解析、加入错题本。
6. 概念库：按章节和知识点浏览定义、解释、公式、例题、易错点及关联知识。

不纳入本阶段：在线聊天生成、云端视觉识别、语音转写、邮件登录、实时课程视频、AI 自动出题和 AI 自动解析。

## 2. 网页入口与自动离线进入

### 在线时

在 DMate 现有导航中增加一个明确的 **“离线版”** 入口。

点击后：
1. 打开本地离线工作区路由（建议 `/offline`）。
2. 检查离线应用外壳、知识图谱、题库和概念库是否已缓存。
3. 若资源尚未准备，显示下载清单和所需空间；用户确认后下载。
4. 完成后显示“已准备，可离线使用”。
5. 离线工作区提供“返回在线版”入口。

### 断网时

通过 Service Worker 接管 DMate 站点的导航请求：
1. 正常联网时优先访问网络。
2. 网络请求失败或超时后，返回已缓存的离线应用外壳。
3. 离线工作区只读取本地资源与本地数据库，不等待云端 API。
4. 网络恢复后提示“网络已恢复”，后台提交待同步数据；不强制刷新页面、不打断用户当前操作。

实现上使用 Service Worker、Cache Storage 和 IndexedDB。Service Worker 缓存应用外壳和静态资源；IndexedDB 保存结构化学习数据和待同步队列。不能只缓存一张离线提示页，否则题库、概念库和编辑功能仍然无法使用。

### 必须明确的首次使用限制

浏览器无法在用户从未访问过 DMate、从未安装或缓存离线资源、且当前完全断网的情况下，凭空打开 DMate 页面。

因此，用户至少需要在有网络时访问一次 DMate，并完成离线资源准备。之后才能在断网时自动进入离线工作区。若用户清除网站数据、换浏览器或使用新设备，也需要重新准备一次。

浏览器的“无网络”判断不能只依赖 `navigator.onLine`；它只是提示信号。真正的降级应以导航请求失败、Service Worker 缓存命中和 API 请求失败为依据。

## 3. 本地数据与同步

### 本地存储

- IndexedDB：错题、笔记、绘图文档、个人学习状态、题目作答记录、待同步操作。
- Cache Storage：离线 HTML、CSS、JavaScript、MathJax、本地知识图谱、题库和概念库资源包。
- localStorage：只保留少量外观偏好，不作为题库、笔记或绘图的主要存储。

每次编辑必须先成功写入本地，再显示“已保存在本机”。不能把“已显示在页面”误报为“已同步到云端”。

### 与现有云同步的关系

现有账号同步使用 PostgreSQL、revision 比较和冲突合并，可以作为在线恢复后的同步基础，但不能直接假设所有离线数据都已经纳入同步：

- 错题、概念笔记和账号学习快照已有同步路径，需要验证离线编辑、删除和冲突场景。
- 现有独立绘图库按浏览器本机保存，当前不属于账号云同步快照；若要跨设备同步，必须扩展快照结构和合并规则。
- 游客绘图目前主要是页面内状态，刷新后可能丢失；必须先改成本地持久化。
- 知识图谱、题库和概念库是应用资源，不是个人学习记录；采用版本化资源包更新，不放入个人同步快照。

同步使用操作队列和记录版本，不直接同步正在使用的 SQLite 数据库文件，也不允许旧设备快照无条件覆盖新数据。删除操作需要墓碑或等效版本记录，避免旧设备重新上传已删除项目。

## 4. 内容包设计

- 题库和概念库采用版本化 JSON 数据包，附带内容清单、校验摘要和来源许可清单。
- 内容记录关联现有 `knowledge_graph.json` 节点编号。
- 用户界面全部使用简体中文；内部编号和数学公式不展示为英文说明。
- 题库与概念库可独立更新，不要求重新安装整个 DMate。
- 不将 CC BY、CC BY-SA 和 DMate 自有内容混成一个无法区分许可的包。

首批内容预览见 `offline-content/`。

## 视觉一致性要求

离线工作区不是第二套品牌视觉，不创建独立的配色、字体、Logo 或图标体系：

- 直接复用主站的 DMate 品牌 SVG、原有图标路径和图标线条规格。
- 复用从主站样式中提取的原始主题 CSS，沿用白色、黑色、蓝色主题及现有 CSS 变量。
- 通过主站已验证的外观状态桥接当前设备的主题、主题色、字体大小、面板透明度、气泡透明度、背景适配、遮罩和模糊设置。
- 自定义背景图从现有外观 IndexedDB 读取，并复制到离线工作区本地设置库；原始外观设置不被修改。
- 离线工作区只增加必要的布局和内容样式，不重绘原有 Logo、图标或背景。

## 5. 对现有代码的影响

当前架构有几个必须先处理的事实：

1. 现有 Tauri 桌面壳的 `frontendDist` 和窗口地址指向远程站点；它不是完整的本地离线应用。
2. 现有模板包含清理旧 Service Worker 和历史缓存的逻辑。引入正式离线缓存时，必须只退役旧版缓存，不能把新离线 Service Worker 一并注销。
3. 现有游客错题、笔记和学习状态可能只在页面内存；必须迁移到本地持久化。
4. 现有独立绘图库使用浏览器本机存储，游客数据可能随页面生命周期清空，且绘图库不在当前账号云同步快照中。
5. 现有知识图谱已经随仓库提供，可作为本地资源基础；其节点编号应继续作为题库和概念库的统一知识点标识。

因此实施顺序应为：先把数据可靠保存到本机，再做离线工作区路由和缓存，最后接入资源包与自动同步。不能先做一个按钮，再把未持久化的页面状态称为离线能力。

## 6. 推荐实施顺序

### 第一阶段：本地持久化
- 错题、笔记、绘图和必要学习状态可在刷新、关闭后保留。
- 为游客和登录用户明确分区。
- 增加本地导出与恢复。

### 第二阶段：离线工作区
- 增加“离线版”入口和 `/offline` 页面。
- 将六个模块接入本地数据层。
- 增加离线状态和本地保存状态提示。

### 第三阶段：自动离线进入
- 注册并维护正式 Service Worker。
- 预缓存应用外壳、静态资源、知识图谱和内容包。
- 网络失败时自动回退到离线工作区。
- 验证首次访问、断网、恢复网络、更新缓存和清除站点数据等场景。

### 第四阶段：内容与同步
- 导入经审核的中文题库和概念库。
- 版本化资源包。
- 扩展绘图等数据的账号同步。
- 验证多设备同时编辑和删除冲突。

### 第五阶段：桌面端
- 将离线工作区及必要静态资源随 Tauri 安装包打包。
- 桌面端离线启动不再依赖远程首页。
- 在线站点更新与桌面端安装包更新分别管理。

## 7. 验收标准

- 完成一次在线准备后，断网并重新打开 DMate，能自动进入离线工作区。
- 断网时六个模块可用；不触发云端 AI、OCR、语音或登录请求。
- 错题、笔记和绘图在断网编辑后，刷新和重启浏览器仍然保留。
- 恢复网络后，待同步数据能自动上传；冲突不会静默覆盖。
- 清除缓存、首次访问和新设备场景有清楚提示，不承诺“从未准备也能离线打开”。
- 内容包的版本、中文质量、来源和许可证可以逐条追溯。
