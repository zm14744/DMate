# DMate

DMate 是面向离散数学学习的智能辅学应用。它把文字问答、图片识题、图论绘图、练习生成、错题订正、概念笔记、知识图谱和学习回顾放在同一工作区，帮助使用者完成“提出问题 → 核对条件 → 获得讲解 → 整理错题与概念 → 复测”的学习流程。

**在线使用：<https://dmate.zeabur.app/>**

可以直接通过浏览器访问，也可以使用 Android 或 Windows、macOS、Linux 客户端。客户端加载同一远程网站；安装包不包含离线大模型，也不在设备上运行 Python 服务端。AI 回答、自动识图、语音转写、账号和云同步都需要联网。

本文按仓库当前实现介绍功能、使用方法、数据保存方式和部署入口。各发行渠道的旧安装包、线上环境变量及第三方模型权限可能与源码不同，具体以实际部署和安装版本为准。

## 功能总览

| 功能 | 可以完成的操作 | 使用时需要区分的事情 |
| --- | --- | --- |
| 教学对话 | 提示引导、完整解析、概念讲解、练习出题、答案诊断 | 默认解题先给提示；是否收录为正式题目由题目标记控制 |
| 图片工作区 | 多图上传、自动识别、局部框选、来源选择、逐图核对和题目分组 | 识别与解题分两步；保存核对结果不会立即发送 |
| 独立绘图 | 新建画板，编辑顶点、边、端点、箭头、权值、边名与布局 | 游客只留在当前页面；登录后的绘图库只保存在当前设备 |
| 错题本 | 收录和编辑题目、整理解析与笔记、订正、同类复测、筛选和导出 | AI 生成的复测题及判断也需要核查 |
| 概念笔记本 | 记录原文、搜索概念、解释所选笔记、分析多概念关联 | AI 只读取本次所选笔记，不直接改写原文 |
| 学习回顾 | 综合聊天、错题、绘图和笔记，用三个模块回顾记录 | 没有内容时显示“无”；本地规则整理，不调用模型或评分 |
| 知识图谱 | 查看课程模块、相关知识点和建议前置关系 | 知识关联不等于学生已掌握，也不等于数学上的严格蕴含 |
| 语音输入 | 将短录音转成可编辑文字，再由使用者发送 | 不自动把转写内容发给聊天模型 |
| 账号与外观 | 邮箱注册、登录、恢复密码、云同步及主题和背景设置 | 云同步不包含本机独立绘图库和背景图片本体 |

## 第一次使用

1. 打开网站。电脑上可同时看到对话列表、聊天区和学习工具；手机上通过顶部入口打开对话列表与学习工具抽屉。
2. 点击“新对话”，在输入区写问题。想把这条内容纳入题目档案时，先将“题目”选为“是”；普通讨论可保留“否”。
3. 点击发送。桌面端 Enter 发送、Shift+Enter 换行；移动端回车用于换行。
4. 默认会先给提示和相关知识。需要完整过程时可以明确写“请给出完整解析”；检查自己的解答时，附上解答过程并说明希望检查的地方。
5. 回答期间，发送位置会显示红色圆形停止按钮。停止后可继续补充条件或重新提问。
6. 需要长期保存聊天、错题和笔记时，再注册或登录账号；游客模式适合临时体验，页面刷新前应自行保存重要内容。

例如，可以先问“等价关系需要满足哪些条件？”，再提交一条具体关系题并标记为“题目：是”。概念讨论和正式题目可以在同一对话中进行，不需要把每次追问都登记为新题。完整操作见[使用指南](docs/USER_GUIDE.md)。

## 文字问答与题目标记

### 如何提出不同类型的请求

教学方式根据本轮文字和当前题目上下文判断，并非要求在一个固定菜单中选择模式。

| 目的 | 输入示例 |
| --- | --- |
| 获得提示 | “这道题先给我一个提示，不要直接给答案。” |
| 查看完整解析 | “请给出当前题的完整解析，说明每一步依据。” |
| 理解概念 | “解释偏序关系，并给出一个不满足条件的反例。” |
| 生成练习 | “出一道中等难度的欧拉图练习，先不要展示答案。” |
| 检查解答 | “这是我的推导……请检查是否遗漏了条件。” |
| 继续当前题 | “当前题的第二步为什么成立？” |

解题默认采用提示引导。生成练习可以提出简单、中等或困难要求；难度属于辅助估计，生成题目不代表已经作答。讨论“上一道题”“第 2 题”时，应确保会话中存在可以定位的题目；遇到歧义，直接附上题干更清楚。

“我要简单题”“我想要一道中等难度的题”等短指令也会进入正式出题流程，生成的练习登记到题目历史，并提供题目标记、图片复制和记错题操作。难度按实际题干判断；小集合笛卡尔积的计数与列举不会仅因包含两个操作就升为中等。旧会话中能根据明确出题请求恢复身份、但尚无有效难度记录的题目先显示“题目”，不会借用其他题目的难度。“我要简单题的答案”或讨论题目标记则仍按对应问答处理。

出题也支持“编一道集合题”“设计一道判断题”“考考我”“我想练习等价关系”“仿照上一题改编一道变式题”，以及明确的英文请求，例如 `Quiz me on set theory`。可以说明知识点、题型、数量、难度和是否展示答案；原文会交给生成流程，仍经过题干、答案和知识点检查。详细汇总见[常见出题问法](docs/USER_GUIDE.md#常见出题问法与普通追问)。数量与难度是生成要求，实际输出仍需要核对。

“给出题目的答案”“求出题目中的未知数”属于解答；“不要出题”、翻译或引用“出一道题”、讨论出题功能也不会仅因出现关键词而生成练习。“简单点”“继续”“我不会”不会单独创建新题。裸“下一题”优先定位历史中已有的下一道题；明确要新题时可说“再出一道同类题”。AI 为明确知识点而提出的澄清问题不登记为正式题目。

### 回答如何逐步显示

新版聊天通过 `POST /chat` 的 SSE 模式接收真实流式正文：普通问答可以在模型尚未生成完整回答时，先显示已经收到的部分，不再固定等整段生成完才播放动画。网络、模型内部推理与请求校验仍影响第一段文字的等待，启用流式不保证立即出字，也不代表模型生成速度本身提高。

浏览器约每 120 毫秒合并一次收到的片段，先清洗和排版，再更新临时回答。尚未闭合的 Markdown 结构或公式会暂缓显示，公式、代码与表格保持完整，不将半个公式源码反复闪在界面上。已经排好的历史回答继续复用；主动向上滚动可暂停自动跟随。流式回答结束后使用服务端的最终正文，不再从头播放一次最长 8 秒的动画。

聊天中的完整裸矩阵、分段函数和对齐公式会先补上公式区域，再进行 Markdown 排版，避免行分隔符丢失或上下标被重复包裹；已经带公式符号的内容和代码示例保留原文。最终排版期间停止回答，不写入这次回答产生的学习、错题或复测记录；排版完成并通过取消检查后，才与最终回答一起处理。

需要完整结果才能校验的路径仍先等待检查，例如练习 / 复测出题、已确认图片或图形结构、可独立精确计算的受支持题型，以及使用已保存参考答案的解答。这类 SSE 连接可以先收到保活信息，待校验完成再收到最终回答，不为了提前显示而跳过题干、图结构、答案或难度检查。普通问答的临时正文也可能被最终校验结果替换。

临时片段不计为已完成的聊天记录，只有最终成功结果保存一次，再沿用原有题目标记、错题、复测和云同步处理。停止、断流、删除关联提问或切换账号会丢弃未完成片段并忽略迟到结果；已发送的用户消息仍保留。服务端会尝试取消后续工作并关闭正在读取的公开正文流，但已发给提供方的请求不保证立即停止或撤销费用；受完整校验保护的旧 JSON 模型读取可能继续到其超时。

整次流式响应最多持续 300 秒，保活消息不会无限延长等待。模型因输出长度限制而续写时，续写仍不完整会明确提示失败，普通问答、图片题和旧 JSON 调用均不把截断正文保存为完整答案。公式还原后统一进行 HTML 清理；代码块中的变量名保持代码原文，不作为裸公式自动改写。

未启用 SSE 的旧客户端和其他 JSON 调用方继续收到原有完整响应；这类兼容回答仍可使用排版后的渐进动画，正文约每秒 140 个字素，长回答动画最多约 8 秒，启用“减少动态效果”时直接显示。代理需要允许实时转发 SSE；并发限额、协议和代理配置分别见[API](docs/API.md#流式响应)与[部署说明](docs/DEPLOYMENT.md#代理容量与运行诊断)。

### “题目：是 / 否”影响什么

- **是**：本条输入作为正式题目，可以进入题目历史、知识分类和学习回顾使用的学习记录。
- **否**：本条作为普通交流，不因出现“证明”“求解”等词就自动新增题目档案。针对已有题目的讲解和追问仍可能关联原题的学习记录。
- 题目标记和回答方式分别处理。例如，标记“否”仍可以询问数学问题；标记“是”也不表示一定直接展示最终答案。
- 文字输入的标记与图片“分组”中的标记分别管理。图片同组多张合并为一道题，不会把图片组号当成会话题号。

## 图片识别、核对与分组

### 上传与自动识别

通过输入区的“＋”选择图片，也可使用支持的拖放或粘贴操作。每批最多 4 张，每张独立处理并保留自己的来源身份。

当前网页自动识图使用 Qwen 读取题干和图形结构，必要时再检查局部连线。读取内容包括文字、顶点、边、方向、权值及可用的位置和外观信息。结果不能只看状态就视为准确，尤其应核对：

- 题干是否包含全部小问、公式、约束和图号；
- 线条交叉处是否真的有顶点，是否漏掉重边或自环；
- 箭头方向、端点连接以及边名和权值是否对应；
- 多个子图的编号、匿名顶点和位置描述是否混淆。

### 原生识别与自主框选

点击“编辑”进入扫描核对窗口。这里的“原生识别”指首次扫描结果，**不代表操作系统自带 OCR**。

当整图读取不完整时，可以切换到“自主框选”，分别选择文字区域和图形区域。选区支持矩形及不规则边界；通过“选择信息”管理需要采用的来源，勾选、排序或删除相应结果，再组成这张图片最终提交的内容。

自主模式采用所选来源，不会自动补入未选中的原生结果。选择的来源尚在识别、失败或没有有效内容时，应先调整来源再保存。删除选区信息会要求确认。

扫描核对窗口的文字、图形区域用于展示识别和所选组合结果；它与独立画板的顶点、边属性编辑不是同一套操作。需要修正扫描内容时，应调整选区与来源；需要自己绘制或逐项编辑图结构时使用“绘图”。

### 保存后与发送后的界面

“保存”会校验当前内容并关闭核对窗口，**不会发送给聊天 AI**。保存后的卡片内容区只显示“已核对”和“编辑”按钮；题干、图结构、保存提示和要求输入框不再铺在卡片外部。点击“编辑”可以回到核对窗口查看或继续调整。

“要求（可选）”留空就不生成“我的要求”段落，也不替使用者编写个人要求。已经填写的要求会随对应图片保留，可回到编辑窗口查看。

发送后立即回到普通聊天输入框，等待 AI 回答期间保留红色停止按钮。未完成的图片任务在处理中保留；取消或出错后重新展示，便于调整和重试。已经成功完成的组不会因为后续组失败而重复发送。

### 多张图片怎样分组

在图片工作区打开“分组”，逐张设置组别和是否为题目。默认每张各一组。

例如上传三张图片：第 1、2 张是同一道题的上下半页，第 3 张是另一道题，可将前两张设为同组，第 3 张保留独立组。前两张按上传顺序组合并获得一份回答，第 3 张单独回答。

组内任意图片标记为题目，该组就按一道题记录；组内全为“否”时不计入正式题目统计。系统会先完成整批必要的确认，再按组请求回答。未手动保存的有效结果在发送时也会经过确认，不能绕过确认直接作为可信图结构使用。

多图中的顶点编号通常只在各自子图内有效。提问“从 1 到 2 的路径”时，最好指明“图片 2 的图 1”，避免把两张图的匿名编号混在一起。

## 独立绘图

学习工具中的“绘图”提供独立画板，用于自己构造图论示例，或按题意重画图形。

1. 新建空白页或打开历史绘图，必要时修改名称。
2. 使用绘图工具添加顶点和边，选择对象后编辑属性。
3. 按需要选择无向 / 有向、无权 / 带权，修改边的端点、边名、权值、曲线或自环。
4. 通过撤销、重做修正操作；用缩放和平移浏览画板，“适应”按实际内容调整视图。
5. 在“图形信息”中检查当前结构。顶点位置和外观描述随当前坐标与编辑更新，不将交叉线条自动当成相连顶点。

完成后有三个不同出口：

| 操作 | 结果 |
| --- | --- |
| 导出图片 | 将当前画板输出为 PNG；移动浏览器可能显示预览，支持的 Android 客户端可保存到相册 |
| AI 指导 | 按当前图结构与填写的要求提供解释，不自动修改画板，也不自动新增正式题目 |
| 上传 | 将当前绘制结构与导出图加入图片工作区，核对、分组并发送后进入对话；以已绘结构为准，不重新猜测导出图中的连线 |

每个绘图工作区最多保留 50 张画板，保存方式取决于是否登录：

- **游客**：只在当前页面内存中保留。关闭绘图弹窗后，在同一页面重新打开可继续查看多张画板；刷新或关闭网页后清空，不使用 localStorage 或 sessionStorage 恢复。
- **登录账号**：自动保存到当前浏览器按账号分区的 localStorage，刷新后可继续打开，但不参与云同步。换设备登录不会出现原设备的画板，清除网站数据会删除它们。

旧版保存在本机的游客绘图库会清理，不会导入新的游客工作区。需要保留的画板请在当前页面导出；删除历史绘图有确认弹窗。

## 错题本、笔记本与学习回顾

### 错题本：从收录到复测

从题目消息中收录需要整理的题目。含多道题的内容可选择实际需要收录的部分，并在保存前检查题干，避免把聊天开场白、提示或答案误存成题目。

保存前的弹窗分为上下两块：上方“题目预览”完整显示只读的 Markdown 与数学公式排版，下方“编辑题目”可修改原文。编辑后，上方会随之更新；点击“确认”才将当前编辑框的题干加入错题本。选择多道题时逐道确认，关闭窗口只放弃尚未确认的题目，已确认的条目仍保留。

错题条目支持编辑题目、整理解析和笔记、记录订正，以及生成同知识点的复测题。“编辑错题 / 学习笔记”弹窗只提供“题目内容”和“我的笔记”两项。修改题干后，旧分类、参考答案与解析等派生内容会清理并重新处理；个人笔记、错因与已有复测历史仍保留。

学习流程为“待订正 → 已订正待复测 → 已通过复测”。复测不通过时可继续回看原题和订正。题目及 AI 判断需要核查，特别是答案不唯一、证明过程或条件复杂的题型。

支持搜索、筛选、排序、单题复制和导出当前筛选结果为 PDF。当前最多保留 240 条错题。

“错误次数最多”按相同题目在错题本中保留的记录条数降序排列。例如题目 A 有 3 条、题目 B 有 2 条，A 的记录排在 B 前面；条数相同时按最近更新时间排列。每条记录计一次，手动收录也计入，答错和复测失败计数不参与这个排序。相同题目按完整题干归一空白后比较，保留大小写差异；不自动合并或删除重复记录。搜索和状态筛选使用整个错题本的记录条数，删除记录或修改题干后重新计算。

### 笔记本：原文与 AI 分析分开

新建概念后填写名称和正文，输入时自动保存；可以搜索已有概念。打开某条笔记不等于选中它：要使用 AI，先勾选对应笔记。

- 选择一条或多条后，可请求“AI 解释”。
- 选择至少两条后，可请求“分析关联”。
- 可附加本次希望关注的问题，例如“比较这些定义的适用条件”。
- AI 仅接收本次选择的概念原文和补充要求，不读取未选笔记、全部聊天或错题，不直接覆盖原文。

笔记内容改变、被删除、换选或关闭时，旧的分析结果不会写回其他笔记。一般容量为 100 条、合计 180,000 字符；每条名称最多 160 字符，正文最多 6,000 字符。单次 AI 分析最多 12 条、合计 24,000 字符。

### 学习回顾：用三段文字整理下一步

学习回顾在浏览器内综合当前保留的聊天学习记录、错题、独立绘图与概念笔记整理概要，打开时不调用模型。有内容时按以下三个模块纵向排列：

| 模块 | 展示内容 |
| --- | --- |
| 最近学习 | 概括现有记录中的学习主题和内容，帮助回想当前学习方向 |
| 值得再看看 | 根据尚需订正、复测或继续梳理的记录，提示可回顾的内容 |
| 接下来可以做 | 选择一个有依据的目标，说明具体自测动作与核对方法 |

**读取范围**：

| 来源 | 纳入的内容 | 边界 |
| --- | --- | --- |
| 聊天 | 当前保留会话中的正式题目，以及用户消息中明确提及离散数学主题的普通概念交流 | 不要求概念追问先标成题目；普通问候、产品操作、仅在 AI 回复中出现的主题不据此新增学习记录 |
| 错题本 | 当前未删除的题干、知识标签、订正状态、复测会话及用户手动通过标记 | 手动收录不等于答错；重复收录仍是独立记录，回顾不合并原题、不修改计数 |
| 概念笔记 | 当前笔记的名称和正文，包括只有标题但还没有正文的笔记 | 空名称且空正文不算内容；删除标记由笔记模型处理；AI 分析结果不代替用户原文 |
| 绘图 | 当前身份下非空画板的名称、文字、顶点、边、方向和权值 | 空白画板不计入；游客仅当前页面内存，账号仅自己的本机图库；绘图库不跨设备同步 |

四种来源都会参与摘要和目标选择。为避免概要过长，“最近学习”只摘取有限主题，以及错题、笔记、绘图各自的一条代表记录，不是完整目录。记录有真实时间字段时按时间排序；旧聊天没有消息时间，只保留会话内相对顺序，不从会话 ID 推算日期，也不宣称“今天 / 本周学了什么”。更新笔记或错题的时间也不代表学习时长。

**建议如何选择**：优先选择有明确复测失败的待处理题，再考虑待订正、已订正待复测的记录；没有这些事项时，参考有内容的近期记录。已有通过记录时可以建议下次学习做一个小变式，不把一次通过写成“已掌握”。手动勾选通过会被读取；旧勾选不能覆盖较新的失败，新复测尚未完成或判定归属不清时提示核对，不套用上次结果。

建议按主题给出可执行动作，例如：量词先写论域、改写否定并核对量词互换；关系性质用具体元素或有序对检验并找反例；计数先区分顺序与重复，再枚举小规模情况；证明写清已知、待证与每一步依据。笔记侧重遮住原文回忆、例子和定义条件；绘图侧重顶点、边与邻接矩阵的对应。仅当主题确实相关时，才建议对照另一条笔记，不把所有资料强行关联。主题不明确时使用通用的定义、例子与条件核对，不编造具体薄弱点。

这些做法参考主动回忆、间隔复习、例题与独立解题交替，以及数学证明策略的研究，来源与适用边界见[参考资料](docs/REFERENCES.md#学习回顾与学习建议)。它是本地规则生成的学习提示，不是自动阅卷、完整语义理解或经过学习效果验证的测评系统；隐含主题、只有代词的追问可能无法识别。

完全没有内容时，窗口正文只显示“无”；有内容时，某个模块缺少相关依据也显示“无”，不添加空白引导文案。每个模块使用概要文本，不展示数字面板、评分、档案、筛选或快捷按钮，也不编造学习活动、学习时长或掌握情况。删除或修改原始记录后，下次打开时按剩余内容重新整理：旧学习事件只辅助同一会话中仍有内容依据的主题，不能独自让已删内容重新出现。已经独立收录的错题、笔记与绘图仍按各自记录保留。

正式题目标记、图片分组和知识图谱的题目索引仍分别生效；学习回顾只是它们之上的文字摘要，不改变题目是否收录，也不替代错题本或笔记本的管理操作。

## 知识图谱、语音与外观

### 知识图谱

图谱包含 10 个模块、68 个知识节点：命题逻辑、谓词逻辑、证明与归纳、集合与关系、函数、初等数论、计数与组合、递推关系、图论、代数结构。

可按当前题、当前会话或历史记录聚焦相关知识，查看节点说明及建议前置关系。支持缩放、拖动、适应视图及复制图谱 PNG；移动端打开时按可用区域自适应，也可进入完整查看。浏览器不支持图片剪贴板时会尝试下载。

图谱展示课程关联，不计算学生掌握度。打开图谱时的历史分类使用本地规则，不因为打开页面就自动调用语义模型；错题本对旧分类的后台补全属于另一条处理路径。

### 语音输入

点击麦克风开始录音，再次点击结束。转写文字插入输入框当前光标位置，可修改后再发送，单段最长 60 秒。

录音需要 HTTPS 或浏览器允许的安全本地环境，并获得设备权限。切换会话、打开编辑器、进入图片工作区或切到后台会取消录音；迟到结果不会插入新的会话。转写失败会保留原有输入。旧 Android 安装包缺少原生权限支持时，需要更新客户端或改用支持录音的浏览器。

### 外观与移动端

支持跟随系统、白色、黑色和蓝色主题，也可设置强调色、字号、自定义背景、背景适配、遮罩、模糊与面板透明度。默认及恢复默认都采用跟随系统。

用户消息气泡随强调色显示为蓝色、绿色或紫色，在白色、黑色和蓝色主题下保持同样的配色规则，气泡透明度单独调整。“跟随系统”按设备的明暗设置切换白色或黑色主题；回到页面时也会重新读取。Android 安装包需包含支持系统明暗变化的原生宿主主题，旧包的固定浅色主题不能仅靠网页更新替换。

移动端使用适合触控的抽屉、对话框和选择弹窗。文件选择器、剪贴板、麦克风、相册和 PDF 导出受系统与浏览器能力影响；桌面浏览器与安装壳可能采用不同的系统窗口或权限流程。

## 账号与数据保存

### 账号提供什么

注册需要用户名、邮箱、密码和邮箱验证码；支持用用户名或邮箱登录。注册成功会返回一次恢复码，应自行妥善保存。账号面板还提供邮箱绑定或更换、邮箱或恢复码找回密码、更换恢复码、退出和永久注销。

登录后，会话、学习记录、错题和概念笔记可以在本机缓存并同步到账号。外观参数由当前设备保存，不随新快照跨设备同步。多设备同步使用修订号处理冲突，前端合并重试，必要时保留冲突副本。退出前应留意同步状态，不能把“已经在页面显示”当作“已经写入云端”。

本地修改后等待 200 毫秒合并连续编辑，再尝试上传；连续编辑最长等待 1 秒就安排一次上传，不会一直重置等待。这些间隔不是完成上传的时间承诺。另一端前台在上一轮检查结束后等待 1.2 秒再次检查，后台等待 30 秒，恢复前台或网络时立即尝试。已经保存的本机编辑优先上传，不受远端快照的界面编辑锁阻挡；远端内容只在安全时应用，避免中断回答、识图或笔记编辑。

同步 HTTP 请求具有有界等待：普通请求预算 15 秒，大体积上传、较大响应或响应大小未知时放宽至 120 秒，兼顾断网恢复与慢网下的大快照传输。失败保留本机待同步标记并自动重试，避免网络挂起后一直停在“同步中”。上传期间新产生的本机编辑继续排队；没有远端冲突时，不为确认一次旧快照上传而重建当前编辑页面。同账号发生冲突合并时，已经收到且仍属当前会话的回答会先完成保存，再进入合并和后续上传。超时不证明服务端一定没有写入，后续请求仍按修订号检查并合并；容量超限会单独退避并提示处理，不循环强制覆盖。

新客户端用一次条件读取同时检查修订号并获取变化的 `sessions` / `learning` 分段：没有更新时不读取或下载快照正文；有更新时只返回哈希不同的分段，版本、摘要和内容来自同一条数据库记录。旧服务端或旧客户端仍可使用原有版本号、摘要、分段接口。相比连续三次请求，新流程减少了有更新时的两次网络往返；实际同步完成时间仍受网络、数据库、历史数据量和冲突重试影响。上传仍采用完整快照与版本比较，不通过强制覆盖提速。

### 各类数据保存在哪里

| 数据 | 游客状态 | 登录状态 | 换设备能否恢复 |
| --- | --- | --- | --- |
| 对话、题目与学习记录 | 当前页面内存，刷新或关闭不保证保留 | 本机账号缓存与 PostgreSQL 云同步 | 成功同步后可以 |
| 错题、概念笔记 | 当前页面内存 | 本机账号缓存与云同步 | 成功同步后可以 |
| 主题、字号等外观参数 | 本机设置，具体持久化取决于页面模式 | 当前设备的本机设置 | 不随云同步恢复 |
| 自定义背景图片本体 | 页面内 Blob | 当前设备 IndexedDB | 不随云同步恢复 |
| 独立绘图库 | 当前页面内存；关闭并重开绘图弹窗可继续，刷新或关闭网页后清空 | 当前浏览器按账号分区的 localStorage | 不可以 |
| 未发送图片、框选草稿 | 当前页面任务 | 当前页面任务 | 不作为完整草稿库恢复 |

退出会清理前端学习缓存并返回游客工作区；未同步内容可能丢失。永久注销删除账号及关联云端学习数据，不能远程清除其他设备、导出文件、运维备份或第三方副本。本机图库和背景需另行通过对应功能或浏览器网站数据管理处理。

数据库临时不可用与主动退出是两种状态：临时故障返回可重试的账号服务错误，保留登录 Cookie 和本机账号缓存；在服务器重新验证身份前，不显示或上传尚未验证的私人缓存。同步快照写入本机时也须完整成功，不能仅收到云端版本号就显示“已同步”；缓存容量不足或组件加载失败时保留当前页面的数据，继续等待恢复。重要内容仍应自行导出备份，清空浏览器网站数据或主动退出可能删除未同步内容。

数据发送给哪些服务、认证与删除的具体边界见[数据与隐私](docs/SECURITY_PRIVACY.md)。

## 技术架构与模型分工

### 服务与前端

- **后端**：Python 3.10、Flask、Gunicorn；网页和 API 同源提供。
- **前端**：原生 JavaScript、HTML、CSS；MathJax 显示公式，Marked 解析 Markdown，DOMPurify 清洗富文本。
- **账号与同步**：PostgreSQL 存储账号、验证码和学习快照；Cookie 保持登录。
- **图形确认**：独立 SQLite 登记原图与确认文档摘要、身份、修订和有效期，不代替账号数据库。
- **本地识别与计算**：PaddleOCR / PaddleX 前后处理、ONNX Runtime CPU 文字推理、Paddle 版面推理的隔离 worker，以及适用范围内的 NetworkX / SymPy 计算。
- **客户端**：Android WebView、Tauri 桌面壳；加载远程网站，提供平台集成。

公式、Markdown、内容清洗、截图和 PDF 导出所用的五个固定版本库由网站本域的 `static/vendor/` 提供，MathJax 的按需扩展也从本域读取。正常使用不必先连接公共 JavaScript CDN，减少国内网络下资源加载受阻的影响。版本目录允许浏览器长期缓存，业务脚本及更新清单仍禁止旧缓存；上游版本、归档完整性和许可记录见该目录的说明及[第三方许可](THIRD_PARTY_LICENSES.md)。

### 模型各自负责什么

| 任务 | 当前网页使用的服务或模型 | 说明 |
| --- | --- | --- |
| 教学问答、练习、答案诊断 | DeepSeek，默认 `deepseek-flash` | 由文本教学与上下文逻辑组织请求 |
| 笔记解释与绘图指导 | DeepSeek | 分别接收所选笔记或当前画板结构 |
| 自动整图扫描、图形区域重识别 | Qwen `qwen3.8-flash` | 当前 `auto_graph` 主读及按需局部复核固定此模型并开启思考 |
| 自主框选文字识别 | PP-OCRv6 Small，ONNX Runtime CPU 隔离 worker | 复用 PaddleOCR / PaddleX 前后处理，在服务端本地执行 |
| 语音转写 | `qwen-audio-3.1-asr-flash` | 使用配置的数学词库，输出先回输入框 |
| 兼容识别路径 | 按显式后端路由和配置选择 | 不能把兼容适配器的默认模型当作网页自动识图模型 |

当前网页自动扫描不会在失败时自动换到 GLM。服务端保留的兼容流程与可选视觉适配器仍有明确入口，详见[识别流程](docs/RECOGNITION.md)。

### 本地文字识别使用什么引擎

文字框默认使用 **ONNX Runtime CPU** 执行 `PP-OCRv6_small_det` 和 `PP-OCRv6_small_rec`。模型权重仍来自同一套 Paddle 官方 Small 包，构建时转换为 FP32、ONNX opset 17；检测、文字行裁剪、排序、归一化和解码继续使用 PaddleOCR / PaddleX 的实现。没有改成另一套 OCR 模型，也没有增加云端文字识别请求。

当前固定的主要版本为 PaddleOCR 3.7.0、PaddleX 3.7.2、ONNX Runtime 1.23.2、PaddlePaddle 3.3.1、Paddle2ONNX 2.1.0 和 ONNX 1.17.0。Paddle 仍用于 `PP-DocLayoutV3` 版面分析及兼容路径；不能因为文字默认使用 ONNX，就从依赖中直接删除 Paddle。完整安装版本以 `requirements.txt` 为准。

文字推理只使用 `CPUExecutionProvider`，ORT 配置为两个算子内线程、一个算子间线程、顺序执行；识别 batch 为 1，检测长边上限为 1600。方向分类、文档矫正和独立公式模型不在这个文字 worker 中启动。布局和文字阶段继续串行运行于独立短生命周期进程，模型不常驻 Flask 进程。

模型转换放在镜像构建或手工缓存准备阶段，运行请求不临时转换模型。ONNX 文件缺失、损坏或引擎初始化失败时会返回本地识别错误，不会静默换成 Paddle 再占用另一套推理资源。部署者需要回退时，可显式设置 `DMATE_TEXT_OCR_ENGINE=paddle_static` 并重启服务；默认值为 `onnxruntime`。这个变量只选择本地文字执行引擎，不改变网页自动识图、文字来源、图片分组或教学模型。

一次本地比较使用相同权重和前后处理、固定两个逻辑 CPU，对五张图做三轮连续识别：五张合计中位数从 5.24 秒降到 3.91 秒，进程峰值 RSS 从约 1075 MiB 降到 827 MiB，五张文字输出逐字一致。该测试不是用户线上 2 核 / 4 GB 主机实测，未模拟 4 GB 内存限制，样本也不足以给出通用准确率；普通小图基本持平，主要收益来自整页识别和初始化。更换执行引擎的目标是提速和降低内存，复杂公式、下标及图内细小标签仍需核对。

### 文字图像质量处理与重复识别缓存

文字选区总是先识别原图，再根据识别置信度、公式风险和像素质量决定是否补充读取。清晰且高置信的文字可直接使用首遍结果，不因中文 / 英文、长句 / 短句而固定增加一次识别。低对比度、阴影或亮度不均作为补充读取的线索，使用温和的局部对比度调整；深色底可反相后调整对比度，轻微模糊可温和锐化。每次只选择一种处理，最多增加一遍；处理保持原尺寸和坐标，不通过强制二值化、旋转或重新绘制笔画改写原图。

补充读取继续采用保守合并。数字、符号或新增文字区域存在冲突时，差异保留为待核对证据，不直接认定增强后的文字更正确；浅色正文也不会仅因对比度弱就被删除。质量分析也会检查首遍文字框以外的浅色笔画线索，避免仅因已识别文字高置信就忽略可能漏掉的弱字。它只是选择是否恢复读取的线索，不是正确性认证。

六张本地样本的新旧预处理核对中，清晰英文和中文题干可省去一遍补充读取，六张输出正文保持逐字一致；原有公式答题横线缺失仍然存在。这是小样本核对，不能推导为所有图片更快或识别精度提高。

`/graph/text-region` 另有短期的服务端机器识别结果缓存。同一浏览器 / 账号、完全相同原图字节、相同有效选区与排除区域、相同顺序 / 编号，且引擎、模型清单和预处理版本一致时，可复用已完成的非空结果。失败、空结果、待核对或部分结果不进入缓存；图片原件、使用者编辑内容、确认凭据及 worker 回执不放入该缓存。

缓存每个 Web 进程最多 64 条，序列化结果合计最多 8 MiB，有效期为 10 分钟；过期条目不再复用，并在后续缓存访问时清理。进程重启即清空，不写磁盘、数据库或 Redis，也不跨进程共享。每次命中仍核对本次原图来源与身份，重新绑定当前请求，并处理取消状态。API 可用 `force_recognition=1` 清除当前匹配项并实际重识别，响应中的 `cache_hit` 区分是否复用了机器结果。

结果缓存只能减少重复、完全匹配请求的等待，不能加速第一次识别。本地真实 API 核对已验证：相同原图与选区使用新的已登记任务 ID 和操作 ID 时可命中，跳过模型 worker，返回内容重新绑定当前 ID。它不是账号学习数据同步，也不改变游客绘图刷新或关闭页面后清空的规则；浏览器刷新和服务器进程重启是两种不同生命周期。具体参数与调用方式见[API](docs/API.md#原图选区接口)。

图形中的未知方向、缺失权值可以使用现有局部复核；空白属性与图类型矛盾不会被当作已经读清。这些处理不增加第三轮视觉调用，也不代表所有公式、重边和细小箭头都能准确识别。

结构校验检查数据格式与一致性，用户确认说明采用哪份结构，数学工具只验证其支持的计算；三者均不能自动证明读图结果与原图完全一致，也不能保证所有 AI 解答正确。

## 本地启动

### 运行前准备

服务端以 **Linux + Python 3.10** 为基线。OCR worker 使用 `fcntl` 等 Linux 系统能力，Windows 自托管请使用 WSL2 或 Linux 容器。桌面客户端支持 Windows 不代表 Python 服务端可直接在 Windows 上运行。

需要 Python 3.10 及 venv、pip、Git，以及 Dockerfile 列出的 OpenCV / Paddle 系统库。依赖包含本地推理框架和模型包，首次安装与下载会耗时并占用磁盘；具体资源需求取决于是否启用本地识别及实际并发，不宜仅按普通 Flask 小站估算。

Debian / Ubuntu 系统库示例（Python 3.10 需事先安装）：

```bash
sudo apt-get update
sudo apt-get install -y libgl1 libglib2.0-0 libgomp1 libsm6 libxext6 libxrender1
git clone https://github.com/zm14744/DMate.git
cd DMate
python3.10 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

`requirements.txt` 会继续安装 `requirements-agents.txt`，不需要再单独重复安装。网页使用原生静态资源，本地启动不需要 `npm install` 或前端打包。

### 配置需要使用的功能

应用在模块初始化时从进程环境读取配置，项目没有在此之前自动加载 `.env` 的步骤；**仅创建 `.env` 文件不能代替注入环境变量**。可以在终端导出变量，也可以由容器或部署平台注入。以下值都是需要自行替换的占位内容：

```bash
export DEEPSEEK_API_KEY='替换为自己的DeepSeek密钥'
export DASHSCOPE_API_KEY='替换为自己的DashScope密钥'
# 按账号实际地域和工作空间设置 DASHSCOPE_VISION_API_URL。
# 仅替换 Key 不代表可以访问源码默认配置的工作空间。
```

| 希望启用的功能 | 必要配置 | 未配置时的行为 |
| --- | --- | --- |
| 打开网页、临时使用本地界面 | Python 依赖与系统库 | 不要求先配置账号数据库 |
| AI 问答、练习、笔记分析、绘图指导 | `DEEPSEEK_API_KEY` | 相应 AI 请求报服务配置错误 |
| 网页自动识图、图形选区识别 | `DASHSCOPE_API_KEY` 与有权限的视觉服务地址 | 对应视觉请求无法完成 |
| 语音转写 | DashScope 配置及可访问的语音模型、词库 | 语音服务不可用，不自动改换模型 |
| 文字框 OCR | ONNX Runtime、PaddleOCR / PaddleX 依赖、可写缓存及已转换模型 | 需要先准备本地模型，不能靠视觉 Key 替代 |
| 登录与云同步 | `DATABASE_URL`、稳定的 `AUTH_SECRET_KEY` | 可打开游客页面，账号与同步不可用 |
| 邮箱注册、绑定与邮箱找回 | Brevo 或 SMTP 配置 | 无法完成依赖验证码的邮箱流程 |

需要本地账号调试时，再配置自己的 PostgreSQL，例如：

```bash
export DATABASE_URL='postgresql://dmate:替换为数据库密码@127.0.0.1:5432/dmate'
# 生成一次并妥善保存，后续启动继续使用同一个值。
export AUTH_SECRET_KEY="$(python -c 'import secrets; print(secrets.token_hex(32))')"
export SESSION_COOKIE_SECURE=0
```

最后一项仅用于本地 HTTP 调试；生产 HTTPS 保持默认安全 Cookie。数据库账号需要初始化账号表和补列的权限。注册还需要可用邮件通道；仅配置数据库不能发验证码。数据库 DSN 中的特殊字符应按 PostgreSQL URI 规则编码。

### 准备本地模型并启动

需要本地文字或版面模型时，先下载官方包并准备文字 ONNX 模型到可写缓存：

```bash
export DMATE_MODEL_CACHE_DIR="$PWD/.model-cache"
export PADDLE_PDX_CACHE_HOME="$DMATE_MODEL_CACHE_DIR/paddlex"
python scripts/prepare_ocr_model_cache.py --cache-dir "$DMATE_MODEL_CACHE_DIR"
python scripts/prepare_ocr_model_cache.py --cache-dir "$DMATE_MODEL_CACHE_DIR" --verify-only
python app.py
```

访问 <http://localhost:5000/>。`PORT` 可以覆盖本地端口；`python app.py` 适合本地调试，生产使用 Gunicorn。缓存准备会下载三个官方包、转换两个文字模型、检查模型格式并写入哈希清单；它不执行图片识别，也不发送付费模型请求。首次转换需要额外时间和内存；后续完整缓存可复用。

默认文件布局如下；`PADDLE_PDX_CACHE_HOME` 显式配置时以该目录代替下图的 `paddlex`：

```text
.model-cache/paddlex/
├── official_models/
│   ├── PP-DocLayoutV3/          # 原始 Paddle 版面包
│   ├── PP-OCRv6_small_det/     # 原始文字检测包，保留转换来源与显式回退
│   └── PP-OCRv6_small_rec/     # 原始文字识别包
├── onnx_models/
│   ├── PP-OCRv6_small_det/     # ONNX、原配置与来源哈希记录
│   └── PP-OCRv6_small_rec/     # ONNX、原配置与来源哈希记录
└── dmate-model-manifest.json   # 原包与转换文件的身份和哈希清单
```

`--verify-only` 只检查已有缓存和清单，不下载、转换或执行识别；缓存不完整时会失败。旧版本仅有 Paddle 包时，应先运行不带 `--verify-only` 的准备命令补齐 ONNX；原清单先核对通过后再升级，不能删除清单来掩盖原模型文件发生变化。

## 容器与生产部署

Dockerfile 使用 `python:3.10-slim`，安装系统与 Python 依赖，预下载本地模型包、构建文字 ONNX 模型并核对缓存，再生成平台图标。构建需要访问相应包源和模型源；平台会复用未变化的依赖和模型构建层。

```bash
docker build -t dmate .
docker run --rm -p 8080:8080 \
  --env-file /secure/path/dmate.env \
  -v dmate-state:/data \
  -e DMATE_GRAPH_CONFIRMATION_DB=/data/graph-confirmations.sqlite3 \
  dmate
```

`/secure/path/dmate.env` 由部署者在仓库外创建，包含所需环境变量；示例不自动提供 PostgreSQL 或邮件服务。默认容器监听 8080，平台注入 `PORT` 时按其值监听。HTTP 本地调试与生产 HTTPS 的 Cookie 设置需要分别处理。

构建时先从 ModelScope 的官方 PaddlePaddle 仓库下载三个模型的必需文件，按固定文件版本、大小和 SHA256 校验，支持同次准备中的断点续传及有限重试；不可用时再尝试 PaddleX 的官方来源。原始模型、两个文字模型的 ONNX 导出及最终清单全部校验通过才完成此步骤。若日志出现模型下载超时或 404，构建失败表示模型尚未准备完成，不能以跳过校验处理；具体缓存目录、下载预算和手工准备命令见[本地模型与缓存](docs/DEPLOYMENT.md#本地模型与缓存)。

默认生产入口为：

```bash
gunicorn -w 1 --threads 8 --timeout 300 -b 0.0.0.0:8080 app:app
```

保持单 worker、多线程的原因是上传准入、部分限流、取消和本地推理调度仍含进程内状态。不能只增加 worker 或副本就认为这些状态已经共享；SQLite 确认登记的共享能力不代表其他状态也已共享。

生产配置的重点：

- 由反向代理或平台提供 HTTPS，保留稳定的账号签名密钥。
- PostgreSQL 负责账号与学习数据持久化，图形确认 SQLite 使用可写持久卷。
- 模型缓存与临时目录应可写；推理并发应与可用内存匹配。
- 代理请求体和超时需覆盖图片上传及后端处理预算。
- 只把实际可信的代理网段填入 `TRUSTED_PROXY_CIDRS`，不要直接信任任意转发头。
- API Key、数据库密码、邮箱凭据和签名证书都通过运行环境或发布平台管理，不写进网页或安装包。

`/health` 表示进程和源码状态，`/ready` 提供识别阶段信息；两者返回 HTTP 200 并不表示数据库、邮件与所有模型都已可用。完整配置、邮件字段、缓存、持久化和排错步骤见[部署说明](docs/DEPLOYMENT.md)。

网页变化通常无需重新打包；原生权限、可信来源、更新逻辑和包元数据变化需要重新构建客户端。把服务迁移到自己的域名时，应同时核对 Android / Tauri 中的来源限制，不能只改页面链接。

客户端检测到网页新版本后，有其他会话正在回答、图片待处理、录音或云同步未完成时，会延后自动刷新。访客的聊天、笔记、错题和非空绘图只保存在当前页面内存中，有这些内容时也不自动刷新；用户主动关闭或刷新页面仍会清空访客内容。

GitHub Actions 生成 Artifact 与对外发布安装包是两步，不能把“构建成功”当作“所有下载入口已经更新”。macOS 没有完整签名凭据时只生成标记为测试用途的未公证产物，具体见[macOS 构建与分发](docs/MACOS_DISTRIBUTION.md)。当前网页不提供 PWA 安装；iPhone / iPad 的下载入口提供 Apple Web Clip 描述文件，安装后可从主屏幕以全屏网页模式启动 DMate。它仍是网站入口，不等同于原生 iOS App。

没有配置自建下载地址时，安装入口优先提供 GitCode 的对应文件直链，并保留 GitHub 等备用渠道；部署者设置的有效 HTTPS 下载地址会优先使用。GitHub 下载使用固定发行标签和文件名，避免 `latest` 切换到其他发行版后找不到旧文件。安装后更新清单同样提供 GitCode 主源和同发行版 GitHub 备用源，只接受本仓库受限下载路径；它的版本号与 `published` 状态仍以实际发布为准，网页修改不会自动生成新 APK、EXE 或 DMG。

公开下载可用性应使用 GET 或小范围 Range GET 检查，不能只凭 HEAD：当前 GitCode 附件接口对 HEAD 可能返回 404，而对应 GET 可返回真实文件及 206 分段响应。国内源的存在不代表已经覆盖大陆所有运营商网络；页面资源同域化、公开文件可获取和用户设备实际下载安装是不同的验证范围。

## 容量、限制与常见问题

### 主要容量

| 项目 | 当前限制 |
| --- | --- |
| 每批图片 | 4 张 |
| 单张图片字节数 | 20,000,000 字节；不是 20 MiB |
| 普通上传图片解码像素 | 最多 33,177,600 像素，即 7680 × 4320 的总量；不是单独限制长宽 |
| 绘图上传图像 | 单帧 PNG，最多 24,000,000 像素 |
| 常规聊天 | 单条普通输入最多 20,000 字符；上下文最多 64 条消息、合计 120,000 字符 |
| 已确认图片内容 | 有独立结构与组合上限，不按普通短消息方式处理，过大时需拆分 |
| 语音输入 | 单次最长 60 秒 |
| 独立绘图库 | 每个账号本机图库 / 当前页面游客绘图工作区最多 50 张 |
| 错题本 | 240 条 |
| 概念笔记 | 100 条，名称与正文合计最多 180,000 字符 |
| 单次笔记 AI 分析 | 最多 12 条、合计 24,000 字符 |
| 云同步快照 | JSON 编码后最多 12 MiB |

容量达到上限、浏览器存储不足或同步失败时，应先处理提示、导出或删减内容，不要直接刷新页面期待自动恢复。接口还有限流与并发控制，完整条件见[API](docs/API.md)。

64 条包括用户消息和 AI 回复，不是 64 轮，也不是聊天窗口只能保留 64 条。请求优先携带当前题的完整条件及最近交流；新题、明确题目追问仍按题目范围组织，不会为凑满 64 条而混入其他题。达到数量或字符预算时移除较早的完整消息，不截断当前题。长题在保存、题目历史和后续追问中的缓存也采用相应边界。

字符预算不等于模型的 token 窗口。若提供方明确返回上下文容量不足，应用最多额外尝试一次移除较早历史，保留当前题和必要指令；仍不足时提示拆分，不偷偷删掉题目条件。单张图片仍为 20 MB，本次没有提高图片或模型回答的输出长度预算。

### 常见问题

**保存核对结果后，为什么没有立即回答？**

保存只是确定这一张图片采用的内容。回到图片工作区检查分组，再点击发送，才开始 AI 回答。

**核对后为什么只看到“已核对”和“编辑”？**

这是收起后的卡片样式。内容仍保存在当前任务中，点击“编辑”查看，不需要把整份识别结果一直展开在聊天输入区。

**为什么没有填写要求，就不出现“我的要求”？**

可选要求留空就保持为空；系统不代替使用者添加个人要求。题干和已确认图结构仍会作为请求内容提交。

**识别结果漏了小问、顶点或连线怎么办？**

重新进入编辑，切换自主框选，调整文字或图形区域并选择正确来源。不要在缺少关键条件时直接发送；也可以使用独立绘图重建需要明确编辑的图结构。

**点发送后图片界面收起了，任务是否丢失？**

发送期间切回正常聊天框，停止按钮仍可用。未完成任务保留在当前页面处理中，失败或取消后会重新显示；这不等于刷新后仍可恢复草稿。

**登录后换设备，为什么绘图或壁纸没有跟过来？**

登录账号的绘图库和背景图片本体只在原设备保存；账号同步包含学习数据和外观参数，不包含这些本机资源。游客绘图只在当前页面内存中，刷新或关闭网页后也不会恢复。

**游客关闭绘图弹窗后还能继续，刷新后却没有了？**

同一页面内重新打开绘图会继续使用内存中的画板；刷新或关闭网页会结束这份临时工作区。游客不再使用浏览器持久存储恢复历史，旧版游客持久图库也不会导入。重要内容请在离开页面前导出。

**页面能打开，但 AI、账号或识别报错怎么办？**

先按功能检查对应配置。DeepSeek、DashScope、本地 ONNX / Paddle 模型、PostgreSQL 和邮件分别负责不同能力；首页或健康接口可访问，不代表这些依赖都已配置完成。文字识别报模型缓存错误时，先在同一运行环境执行缓存的 `--verify-only`，必要时重新运行缓存准备；工作空间无权限、模型不存在、数据库不可达和邮件拒收需要分别处理。

**为什么只拿到提示，没有最终答案？**

默认教学方式偏向提示引导。需要完整过程时明确要求“完整解析”或“给出答案”，并说明所指题目。

**为什么停止后服务商仍可能计费？**

停止用于取消前端等待和可取消的应用任务；已经发出的第三方请求未必能被服务商撤回。停止操作不能撤销已经发生的外部推理费用。

```text
├── app.py                        # 网页、HTTP接口、账号、同步和请求校验
├── ai.py                         # 文本与兼容视觉服务请求
├── teaching.py                   # 教学方式、题目分类与上下文
├── graph_qwen_targeted.py         # 当前网页自动扫描入口

├── graph_confirmation.py         # 来源绑定与确认快照登记
├── ocr_runtime.py / ocr_worker.py # 本地模型与隔离worker
├── ocr_text_engine.py            # 本地文字引擎选择与已准备模型定位
├── ocr_text_preprocess.py        # 像素质量分析与至多一次补充读取
├── ocr_text_cache.py             # 按来源与身份隔离的短期机器结果缓存
├── drawing_guidance.py           # 画板结构指导与上传校验
├── concept_notebook.py           # 所选概念分析的服务端边界
├── voice_input.py                # 语音格式校验与转写适配
├── knowledge_graph.json          # 课程模块、节点与来源
├── templates/index.html          # 页面入口与基础界面
├── static/                       # 聊天、扫描、绘图、笔记、学习回顾等前端模块
├── docs/                         # 当前功能、接口、部署及隐私说明
├── scripts/                      # 图标生成与本地模型缓存准备
├── android/                      # Android客户端
├── desktop/                      # Tauri桌面客户端
├── snap/                         # Snap打包定义
└── .github/workflows/             # 客户端构建与发行工作流
```

图形模块较多，上表仅列主要入口，不表示每次识别都执行所有 `graph_*.py` 文件。实际路由、状态归属、取消与数据边界见[架构说明](docs/ARCHITECTURE.md)。
