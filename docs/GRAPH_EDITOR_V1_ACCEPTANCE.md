# DMate 原图手动描绘 V1：硬指标与进度

更新：2026-10-27，PR #27 开发分支 `codex/graph-editor-cleanup-20261027-a`。

## 已决定的主流程

上传原图 → 生成 **0 顶点、0 边**的 G₁ 空白草稿 → 自由绘制顶点与边 → 可单独框选图形/文字的矩形或 DIY 不规则多边形 → 用户主动点「识别所选文字」，只对选区内像素调用 PaddleOCR → 用户核对题干、图结构与类型 → 保存独立的数学语义和绘图信息 → 解题。

上传阶段 **不调用 Qwen、GLM 或其他图形 AI，也不自动执行 OCR**；没有预定的点和边。原来的全自动图识别链只是兼容老接口，不是当前默认主流程。

历史自动识别冻结范围与指标见 [core-recognition-acceptance.md](core-recognition-acceptance.md)，**不得拿用户手动录入结果冒充自动识别成功**。当前 V1 以程序确定性保真与人工便捷操作验收。

## 硬指标

| ID | 通过条件 |
| --- | --- |
| M01 | 上传合法原图后 G₁ 顶点=0，边=0，图形 AI 调用=0，OCR 调用=0 |
| M02 | 原图加点、拖点、两点连边、自环、重边都能独立操作；交叉线不能自动生成顶点 |
| M03 | 图形矩形/DIY 多边形（3–64 点）选区可编辑并保存；只绑定当前 G₁/G₂；提供聚焦按钮 |
| M04 | 文字矩形/DIY 多边形后，后端必须按 EXIF 校正的原图裁切并将**选区外像素涂白**，再交 PaddleOCR，不能把选区外原文发送识别 |
| M05 | OCR 请求必须匹配浏览器所有者、原图 SHA256 和本图 task ID；错误/跨原图请求不能调用 OCR |
| M06 | 无名点原名 `null`，显示①②等稳定临时编号；原图无名边不生成伪名称；重边保留不同 edge.id |
| M07 | 方向、带权状态分别可设置，未知箭头不擅自填方向；权值 0、负数和符号原样保留 |
| M08 | 图的顶点、边、方向、权值和已确认数学语义的保存/重开必须 100% 一致；绘制几何保存在 `drawing_document`，不得混入解题 snapshot |
| M09 | 统一显示顺序「点、边（只有真实边名）、关系、图形描述（有则显示）」；每条边独立占一行 |
| M10 | 桌面及 390×844 手机可加点/连边/框选；缩放不改原图坐标，触摸命中目标约 40 CSS px 以上 |
| M11 | 开发分支每次快速 Python+Node+Chromium 测试 0 failed/0 error；合并 main 前手动 `full_suite=true` 跑兼容全量验收 |

不为了变绿而删除有效反例、禁用安全绑定或把 AI 未跑当作 AI 识别准确。

## 当前结果与边界

已经写入上传手动模式、OCR 选区掩膜、矩形和多边形选择、SVG 点边编辑、独立保存。最近的快速回归有 **126 passed**（随后版本仍以最新 Actions 为准）。

尚未部署生产 Zeabur，也未用真正 CPU PaddleOCR 在全部用户原图上验证识别率；**这不构成自动识别精度达标的声明**。可打开 `demos/graph-editor-v1.html` 在本地体验绘图，离线 demo 不发起真实 PaddleOCR。
