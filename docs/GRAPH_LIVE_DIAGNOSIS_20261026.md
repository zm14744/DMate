## 已确认的实际内容错误

### L01：边标识协议导致全部边被过滤

`supplement_07` 返回的逐顶点关联记录使用印刷边名作为边 ID，后端记录了 7 次
`invalid_edge:unscoped_new_edge_identity`，最终边数组为空。
此前实现要求不属于 CPU 候选的边 ID 必须以 `new_` 开头；前缀本身不能证明原图中是否有边，
却阻止合法、唯一的其他 ID 进入实际路径校验。

本轮修复接受合法的图内唯一 ID，并将输出边 ID、可选 `candidate_id`、印刷 `edge_label`
明确分开。候选引用仍须唯一绑定且维持原端点关系；像素、方向、重边实例和完整性校验继续执行。
没有显式候选引用时，不凭相同端点或 `visible=true` 猜测对应关系。
拒绝的每条提议保留有界诊断，避免再次只剩一个去重后的错误字符串。

原响应没有保存完整第二轮提议边路径，因此不能声称修复 ID 后这 7 条边就全部正确。
其关联记录还把右侧外弧列到一个不属于该弧的中间顶点，必须继续核对。

### L02：文字标签位置与顶点标记中心混淆

该图 5 个顶点的标签清单正确，但多个坐标位于标签附近，距实际圆点约 26–37 像素。
原有最多 16 像素的位置微调没有解决这类偏差，错误端点也妨碍了后续像素候选生成。

本轮将节点位置与独立原图标记候选关联，保留模型原坐标、移动依据和歧义。
只允许有像素支持且唯一的一对一匹配；不根据图名、预期度数、金标坐标或固定文字偏移补节点。
节点清单、名称和孤立点身份继续由视觉清单和复核决定。

### L03：关键下标仍被错误改写

该图完整的 4 个小问均已保留，但第 3 问的一个顶点下标由 `5` 误读为 `3`。
第二轮解释还引用了图中其他标签和题意逻辑，不能作为该题干字符的原图依据。

本轮第二张复核图同时包含全部子图裁图与题干原像素的局部放大。
文本区域依据本次实际 Paddle 定位框选择、合并，OCR 字符不会绘入图片。
每块附原图像素框、原图归一化坐标和提示 ID，保持所有输出坐标属于完整原图。
紧凑布局减少空白，整张复核图限定为最长边 2200、最多 240 万像素，仍只使用两次视觉请求。
提示要求关键字符以该题干位置的像素为依据，禁止用其他标签或数学合理性替代。

阿里云文档说明 Qwen3-VL 会按 `max_pixels` 对超限图像缩放，OpenAI 兼容接口的默认上限为
2,621,440 像素。局部原像素裁图与紧凑布局用于保留小字的有效显示尺寸，不构成识别正确性的证明。

- [图像与视频理解](https://help.aliyun.com/en/model-studio/vision)
- [OpenAI 兼容 Chat 参数](https://help.aliyun.com/en/model-studio/qwen-api-via-openai-chat-completions)

DeepSeek 的等义编辑保护保持不变；新增有界编辑决策记录，以区分它建议了什么、为什么被拒绝。
此前记录只有拒绝数量，不能倒推当时的编辑内容。

### L04：第二轮传输中断缺少可定位信息

两个不同原图的第二轮均返回外层 `ConnectionError`，但旧指标没有 HTTP 响应阶段或底层异常链。
8–9 秒的耗时不能单独证明连接超时：Requests 也可能把 SSE 读取超时包装成 `ConnectionError`。

本轮补充响应头前、响应体读取、SSE 阶段、底层异常类型链、已接收 HTTP 状态、事件数量和正文字符数。
普通指标不保存异常消息、请求头、密钥、完整 URL 或正文。
不将不完整的流作为完整识别结果，不自动重试，也不增加两次视觉请求的预算。
真实网络根因仍需部署后带有新字段的失败证据确认。

### L05：部署检查不能明确确认新管线

旧 `/health` 主要返回历史模块版本，前端文件一致也不能独立证明新 OCR 开关及后端版本。
本轮 `/health`、`/ready` 增加 `graph_nextgen_enabled`、`graph_nextgen_version`，
与 OCR 共用一个轻量版本常量，便于在实际付费调用前核对部署。
