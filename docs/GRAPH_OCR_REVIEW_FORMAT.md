# DMate 图片识别结果弹窗：统一语言及显示规范

更新时间：2026-10-22。适用范围：**图片核对弹窗**；原有 OCR、千问模型、OpenCV 检测、AI 解题、聊天与其他产品模块保持原样。

## 目标

同一份结构化识别数据，无论 JSON 中顶点、边或多图数组的排列顺序如何，弹窗均用统一的中文字段、排序和数学排版呈现。结构化输出不等于模型推断必然正确，准确率须另行验收。

### 图形信息的固定栏目

每幅图统一为：

- `图 n（原图号）`：完整图形按图号或可信坐标排序。
- `类型`：有向/无向/方向待核对；带权/无权/待核对；简单图/多重图/待核对。
- `顶点（N）`：自然顺序稳定排列，临时标签带下标按 MathJax 渲染。
- `孤立顶点`：如有才显示。
- `边（已记录 M 条）`：边按端点与标签稳定排序；有向边保留箭头方向；重复记录按端点与相同属性合并显示 `×n`，但仍计入总记录数 M。
- `状态`：结构已列出／待核对。前者也不能代替对原图的准确性核实。
- `待核对`：存在未识别边、箭头歧义等时显示，不补造原图中不存在的连接。

### 不一致时的安全降级

后端只能在**最终图形说明仍与 Qwen 规范化边表一致，且没有独立复核问题**的情况下返回 `graph_display_data` 供固定格式渲染。如果复核修改了图形内容，不显示可能过时的原边表，改为展示 `识别说明（结构化边表尚未核实）` 和最终原文。此时语义内容仍可能因模型而变化；不伪造不存在的结构化记录。

### 题目文字与渲染

题目文字保留原有语言和数学内容；不借排版之名翻译、改题或更改题目数字。两栏均使用既有 Markdown + MathJax 公式排版，不再提供文字与图形信息编辑框。下方“本次要求”仍可编辑。前端格式化只用于**显示**，点击“开始”仍提交后端识别的原始 `text` 与 `visual_text`。

### 无新增模型成本

固定格式由前端实现，不产生额外的千问 API 请求。后端只增加一个向后兼容的 `graph_display_data` 字段与 `graph_display_version`，供新前端识别。

## 离线自检

已执行前端 JavaScript 语法检查和少量合成 JSON 样例：调换顶点、边、多图数组顺序后结构化展示一致；重边 `×2`、(v_1) 下标、有向箭头、待核对状态可分别生成。**尚未在真实浏览器与线上 Zeabur 页面完成端到端验收，也未运行任何收费视觉请求。**
